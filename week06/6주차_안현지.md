### 1. 평가 지표의 종류

| 분류 | 사용 목적 | 쉽게 말하면 | 대표 지표 |
| --- | --- | --- | --- |
| **예측 오차 지표** | 모델이 테스트 데이터의 평갓값을 얼마나 가깝게 예측했는지 측정 | 별점을 얼마나 정확히 맞혔나 | MAE, MSE, RMSE |
| **집합 평가 지표** | 모델이 높은 점수를 준 상위 K개 아이템의 추출 능력을 측정. 클릭·구매 여부 같은 이진 분류의 정밀도나 추천 범위를 평가할 때 사용 | 추천 목록 안에 정답이 몇 개 있나  | Precision, Recall, F1-measure |
| **순위 평가 지표** | 아이템 순서를 고려해서 상위 K개가 얼마나 올바른 순서로 나열됐는지 측정 | 정답을 위쪽 순위에 잘 배치했나  | nDCG, MAP, MRR |
| **기타 평가 지표** | 클릭 여부 같은 예측 정밀도 외에 사용자 만족도를 직접 측정 | 정확도 말고 사용자가 만족했나 | 커버리지, 다양성, 신규성, 세렌디피티 |

### 2. 예측 오차 지표

- 실제 평갓값과 예측 평갓값의 차이를 재는 지표. 작을수록 좋다.
    - 예시: 실제 [0, 1, 2, 3, 4], 예측 [0.1, 1.1, 2.1, 3.1, 4.1] → 모두 0.1씩 틀림
- 기호 설명
    
    
    | 기호 | 뜻 |
    | --- | --- |
    | rᵢ | i번째 아이템의 실제 평갓값 |
    | r̂ᵢ  | i번째 아이템의 예측 평갓값 (모자 ^ = 예측값) |
    | n | 아이템 수 |
    | Σ (시그마) | 1번부터 n번까지 전부 더한다 |
    | 1/n Σ | 다 더한 뒤 n으로 나눈다 = 평균 |
    
    #### MAE (평균 절댓값 오차)
    
    $$
    	\mathrm{MAE} = \frac{1}{n}\sum_{i=1}^{n} \left| r_i - \hat{r}_i \right|
    $$
    
    - 차이의 절댓값(마이너스 제거)을 평균 낸 것
    - "평균 몇 점 틀렸나"를 가장 직관적으로 보여준다.
    
    #### MSE (평균 제곱 오차)
    
    $$
    \mathrm{MSE} = \frac{1}{n}\sum_{i=1}^{n} \left( r_i - \hat{r}_i \right)^2
    $$
    
    - 차이를 **제곱**해서 평균 낸 것. 예시 값: **0.01**
    - 제곱하는 이유: 마이너스를 없애고 크게 틀린 것에 벌점을 더 주기 위해
        - A모델: 1점, 1점 틀림 → MAE 1, MSE 1
        - B모델: 0점, 2점 틀림 → MAE 1, MSE 2
        - MAE로는 같지만, MSE는 한 번 크게 틀린 B를 더 나쁘게 평가한다.
    
    #### RMSE (평균 제곱근 오차)
    
    $$
    \mathrm{RMSE} = \sqrt{\frac{1}{n}\sum_{i=1}^{n} \left( r_i - \hat{r}_i \right)^2}
    $$
    
    - MSE에 **루트**를 씌워 제곱된 단위를 원래 점수 단위로 되돌린 것.

- 흐름: 추천 시스템은 별점(명시적 피드백) 예측에서 시작했지만 요즘은 별점이 없는 서비스가 많아 클릭 같은 암묵적 피드백으로 평가하는 것이 주류다

### 3. 집합 평가 지표

- 추천 목록(예측 아이템 집합)과 실제 클릭(적합 아이템 집합)을 비교하는 지표
    - **예측 아이템 집합 (pred_items):** 모델이 클릭할 거라고 추천한 목록. 점수 높은 순으로 정렬
    - **적합 아이템 집합 (true_items):** 사용자가 실제로 클릭한 아이템 = 정답
    - 실제로는 사용자마다 계산한 뒤 **전체 평균**을 낸다.
- 기호 설명
    
    
    | 기호 | 뜻 |
    | --- | --- |
    | C | 적합 아이템 집합 (정답) |
    | R_K | 예측 아이템 집합의 상위 K개 |
    | K | 순위의 길이 (몇 개까지 볼지) |
    | ∩ (교집합) | 두 집합에 모두 들어 있는 것 = 맞힌 추천 |
    | |  | | 집합 안의 개수 |
    
    #### Precision@K (적합률)
    
    $$
    \mathrm{Precision@}K = \frac{\left| \mathcal{C} \cap \mathcal{R}_K \right|}{K}
    $$
    
    - **맞힌 수 ÷ 추천한 수** → "추천한 K개 중 몇 개가 맞았나?"
    - 비유: 던진 미끼 중 물고기가 걸린 비율
    
    #### Recall@K (재현율)
    
    $$
    \mathrm{Recall@}K = \frac{\left| \mathcal{C} \cap \mathcal{R}_K \right|}{\left| \mathcal{C} \right|}
    $$
    
    - **맞힌 수 ÷ 정답 수** → "정답 전체 중 몇 개를 찾았나?"
    - 비유: 호수의 물고기 중 잡은 비율
    - Precision과 분자는 같고 분모만 다르다.
    - 정답이 하나도 없으면 0으로 나눌 수 없으므로 책 코드는 0을 반환한다.
    
    **Precision과 Recall은 트레이드오프 관계**
    
    - K를 늘리면 정답을 더 찾아서 Recall은 오르지만, 틀린 추천도 늘어서 Precision은 떨어진다.
    - 그물을 크게 던지면 물고기는 많이 잡히지만 쓰레기도 같이 걸리는 것과 같다.
    
    #### F1-measure (F1값)
    
    $$
    F1 = \frac{2 \cdot \mathrm{Recall} \cdot \mathrm{Precision}}{\mathrm{Recall} + \mathrm{Precision}}
    $$
    
    - Precision과 Recall의 조화 평균
    - 조화 평균을 쓰는 이유: 둘 중 하나라도 낮으면 F1도 확 낮아지게 해서 한쪽만 잘하는 모델을 걸러 낸다.
        - 예: P = 1.0, R = 0.0이면 그냥 평균은 0.5지만 F1은 0

### 4. 순위 평가 지표

- 정답을 몇 개 맞혔는지뿐 아니라 위쪽 순위에 잘 배치했는지까지 보는 지표
    - 같은 정답 3개라도 1~3위에 있는 게 8~10위에 있는 것보다 좋은 추천이다.

**PR 곡선:** K를 1, 2, 3, …으로 늘려 가며 (Recall, Precision)을 점으로 찍고 이은 그래프

- 가로축 Recall, 세로축 Precision. 시작점은 관례적으로 (0.0, 1.0)

![image.png](6%EC%A3%BC%EC%B0%A8%20%C2%B7%20%EC%95%88%ED%98%84%EC%A7%80/image.png)

| K | 아이템 | 클릭 | Recall | Precision |
| --- | --- | --- | --- | --- |
| 1 | A | ○ | 1/4 = 0.25 | 1/1 = 1.0 |
| 2 | B | ○ | 2/4 = 0.5 | 2/2 = 1.0 |
| 3 | C | ✕ | 2/4 = 0.5 | 2/3 = 0.66 |
| 4 | D | ○ | 3/4 = 0.75 | 3/4 = 0.75 |
| 5 | E | ○ | 4/4 = 1.0 | 4/5 = 0.8 |
| 6 | F | ✕ | 4/4 = 1.0 | 4/6 = 0.66 |
| 7 | G | ✕ | 4/4 = 1.0 | 4/7 = 0.57 |
| 8 | H | ✕ | 4/4 = 1.0 | 4/8 = 0.5 |

그래프 읽는 법

- 정답을 맞히면 → 오른쪽으로 이동 (Recall 상승)
- 오답이면 → 아래로 이동 (Precision 하락)
- 정답을 위쪽 순위에 몰아 둔 좋은 추천일수록 곡선이 오른쪽 위에 붙는다.
- 예시는 데이터가 적어 계단 모양이지만 데이터가 많아지면 곡선처럼 보인다.

AUC (Area Under Curve, 곡선 아래 면적)

- PR 곡선과 두 축으로 둘러싸인 면적
- 0~1 사이 값이고 1에 가까울수록 좋다. 그래프 모양을 숫자 하나로 요약한 것

PR 곡선 vs ROC 곡선

- ROC 곡선의 AUC: 클릭한 것과 안 한 것이 비슷한 비율인 데이터 평가에 적합
- PR 곡선의 AUC: 추천처럼 클릭 안 한 아이템이 훨씬 많은 데이터에서 더 적절

## 중요하게 본 내용

- 가장 기억에 남는 내용: Precision과 Recall이 트레이드오프 관계라서 하나만 보면 안 되고, F1이나 PR 곡선으로 함께 봐야 한다는 점이 기억에 남았다.
- 중요하다고 생각한 이유: 추천을 많이 하면 Recall은 쉽게 올릴 수 있지만 쓸모없는 추천도 늘어난다. 어떤 지표를 보는지에 따라서 모델 평가가 완전히 달라질 수 있기 때문에 중요하다고 생각한다.
- 다른 주제와 연결되는 부분: 5장에서 RMSE는 좋은데 Precision@K는 낮은 결과가 많았다. RMSE는 점수 맞히기, Precision@K는 목록 맞히기를 재는 서로 다른 지표라서였다는 걸 이번 범위에서 확실히 이해했다.

## 질문 및 토론거리

- 이해가 어려웠던 부분: F1-measure가 왜 그냥 평균이 아니라 조화 평균을 쓰는지, PR 곡선과 ROC 곡선이 데이터 비율에 따라 왜 다르게 쓰이는지
- 팀원들과 함께 이야기할 질문: 영화 추천 서비스라면 Precision과 Recall 중 무엇을 더 중요하게 봐야 할까?
    - **이윤성**: 트레이드오프 관계에서 알 수 있듯, 좀 더 정확한 추천 및 안정적인 값 추출의 측면에서 볼 때 Precision@K(적합률) 값이 좀 더 적합할 것으로 보인다.
    - **이동민**: precision이 더 중요할 것 같다. 사용자에게 추천을 제공할때 적합하지 않은 추천을 받았을 때 생기는 소요가 더 크게 느껴질 수 있기 때문이다.
    - **김민서**: 사용자는 추천된 영화 중에 자신이 좋아하는 영화 몇개만 찾아서 보기 때문에 Precision 을 더 중요하게 봐야할 것 같다
    - **노시은**: 적은 수라도 취향에 맞는 영화를 추천하는게 만족도가 더 높을 것 같아 Precision이 더 중요할 것 같다.

## 스터디 후 보완

- 새롭게 이해한 내용: RMSE 같은 예측 오차 지표는 별점이 있어야 계산할 수 있지만 요즘은 별점이 없는 서비스가 많아 클릭 여부로 평가하는 Precision과 Recall이 주류가 되었다. 두 지표는 분자는 같고 분모만 다르다. Precision은 추천한 수로 Recall은 정답 전체 수로 나눈다. 그래서 추천 개수를 늘리면 Recall은 오르고 Precision은 떨어지는 트레이드오프가 생기고 이를 함께 보기 위해 F1과 PR 곡선을 사용한다.
- 수정하거나 추가할 내용: Precision@K는 상위 K개 안에서의 순서는 보지 않는다(정답이 1위든 3위든 값이 같음). 그래서 순서까지 반영하는 MRR, MAP, nDCG와 비교해서 정리하기
