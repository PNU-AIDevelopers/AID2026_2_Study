## 1. Precision-Recall 곡선과 AUC

### 1.1 PR 곡선

![image.png](6%EC%A3%BC%EC%B0%A8%20%C2%B7%20%EA%B9%80%EB%AF%BC%EC%84%9C/image.png)

> Precision과 Recall의 관계를 시각화하여 추천 시스템의 성능을 평가하는 곡선
> 
- Precision → 추천한 아이템 중 실제로 적합한 아이템의 비율
- Recall → 실제 적합한 아이템 중 추천 시스템이 찾아낸 아이템의 비율
- Threshold를 변화시킴 → 관계를 나타냄
- 오른쪽 위에 위치할수록 good

### 1.2 PR-AUC

![image.png](6%EC%A3%BC%EC%B0%A8%20%C2%B7%20%EA%B9%80%EB%AF%BC%EC%84%9C/image%201.png)

> PR 곡선 아래의 면적을 이용하여 추천 시스템의 성능을 평가하는 지표
> 
- 0~1 범위, 1에 가까울수록 good
- 추천 시스템에서 적합한 아이템과 부적절한 아이템의 수가 크게 차이 나는 경우 PR-AUC ?> ROC-AUC

## 2. 순위 기반 평가 지표

추천 시스템에서는 적합한 아이템을 추천했는지도 중요하지만, 적합한 아이템이 추천 목록의 몇 번째에 배치되었는지도 중요함

### 2.1 MRR@K (Mean Reciprocal Rank)

> 추천 순위에서 최초로 등장한 적합한 아이템의 위치를 평가하는 지표
> 

$$
MRR@K=\frac{1}{|U|}\sum_{u\in U}\frac{1}{k_u}

$$

- $U$ → 전체 사용자 집합
- $k_u$ → 사용자 $U$의 상위 K개 추천 결과 중 최초로 등장한 적합한 아이템의 순위
- 상위 K개에 적합한 아이템이 없으면 해당 사용자의 점수는 0

계산 예시

| 최초 적합 아이템의 위치 | Reciprocal Rank |
| --- | --- |
| 1위 | 1 |
| 2위 | 0.5 |
| 3위 | 0.333 |
| 4위 | 0.25 |
| K위 이내에 없음 | 0 |

예를 들어 3명의 사용자가 처음으로 적합한 아이템을 발견한 순위가 각각 1위, 2위, 4위라면

$$
MRR=\frac{1+\frac12+\frac14}{3}\approx0.583

$$

특징

- 최초로 등장한 적합한 아이템의 위치만 고려
- 두 번째 이후에 등장한 적합한 아이템은 평가에 반영되지 않음
- 사용자가 처음 발견한 적합한 아이템을 선택하는 상황에 적합
- 상위 순위에서 적합한 아이템을 발견할수록 높은 점수를 부여

핵심 → 첫 번째 적합한 아이템을 얼마나 빠르게 발견할 수 있는지 평가

### 2.2 AP@K (Average Precision)

> 상위 K개 추천 결과에서 적합한 아이템이 등장하는 위치의 Precision을 평균한 지표
> 

$$
AP(u)@K =
\frac{\sum_{k=1}^{K}c_{u,k}\cdot Precision@k}
{\sum_{k=1}^{K}c_{u,k}}
$$

- $K$ → 추천 순위의 길이
- $c_{u,k}$ → 사용자 \(u\)에게 k번째 아이템이 적합하면 1, 아니면 0
- $Precision@k$→ 상위 k개 추천 결과의 정밀도
- 책의 계산 방식에서는 상위 K개에 적합한 아이템이 없으면 AP를 0으로 처리

계산 예시

상위 5개 추천 결과 중 2위와 4위의 아이템이 적합한 경우

| 순위 | 적합 여부 | 해당 순위까지 Precision |
| --- | --- | --- |
| 1위 | 0 | - |
| 2위 | 1 | 1/2 = 0.5 |
| 3위 | 0 | - |
| 4위 | 1 | 2/4 = 0.5 |
| 5위 | 0 | - |

$$

AP@5=\frac12(Precision@2+Precision@4)

=\frac12(0.5+0.5)=0.5

$$

특징

- MRR과 달리 여러 개의 적합한 아이템을 모두 고려
- 적합한 아이템이 상위에 배치될수록 높은 점수를 부여
- 적합한 아이템이 등장한 위치의 Precision을 평균하여 계산

핵심 → 적합한 아이템들이 추천 목록 전체에서 얼마나 상위에 배치되어 있는지 평가

### 2.3 MAP@K (Mean Average Precision)

> 전체 사용자의 AP@K를 평균한 지표
> 

$$
MAP@K=\frac{1}{|U|}\sum_{u\in U}AP(u)@K
$$

- AP → 한 사용자에 대한 평가
- MAP → 여러 사용자에 대한 평균 평가
- 전체 사용자를 대상으로 추천 순위의 품질을 측정할 때 사용

계산 예시

| 사용자 | 상위 3개 추천 결과의 적합 여부 | AP@3 |
| --- | --- | --- |
| A | [1, 0, 0] | 1 |
| B | [0, 1, 0] | 0.5 |
| C | [0, 0, 1] | 0.333 |

$$
MAP@3=\frac{1+0.5+0.333}{3}\approx0.611

$$

핵심 → 여러 사용자를 대상으로 추천 목록의 평균적인 순위 정확도를 평가

### 2.4 MAP과 MRR의 차이

MAP과 MRR은 계산 방식뿐만 아니라 가정하는 사용자 행동에도 차이가 있음

| 구분 | MAP | MRR |
| --- | --- | --- |
| 평가 대상 | 여러 적합 아이템의 순위 | 최초 적합 아이템의 순위 |
| 사용자 행동 가정 | 여러 적합 아이템을 고려한 뒤 종료 | 최초 적합 아이템을 발견하면 종료 |
| 중점 | 추천 목록 전체의 품질 | 첫 번째 적합 아이템의 위치 |
| 적합한 상황 | 여러 콘텐츠를 탐색하는 서비스 | 원하는 결과 하나를 찾는 서비스 |

책에서는 두 지표를 사용자가 어느 시점에 탐색을 멈추고, 추천 결과에서 어느 정도의 이익을 얻는지라는 관점에서도 설명함

- MAP → 사용자가 순위를 탐색하며 여러 적합 아이템에서 이익을 얻는 상황
- MRR → 사용자가 최초 적합 아이템을 발견했을 때 이익을 얻는 상황

### 2.5 nDCG@K (Normalized Discounted Cumulative Gain)

> 추천 아이템의 적합도와 순위 위치를 함께 고려하여 평가하는 지표
> 

MRR과 MAP은 적합 여부를 주로 0과 1로 평가하지만, 실제 서비스에서는 클릭과 구매처럼 사용자 행동에 따라 서로 다른 이익을 부여할 수 있음

nDCG는 이러한 적합도의 차이와 추천 순위에 따른 가치 감소를 반영함

DCG (Discounted Cumulative Gain)

$$
DCG@K=r_1+\sum_{i=2}^{K}\frac{r_i}{\log_2 i}

$$

- $r_i$ → i번째 아이템의 적합도 또는 이익
- 순위가 낮아질수록 로그를 이용하여 이익을 할인
- 동일한 적합도의 아이템이라도 상위에 위치할수록 더 높은 점수를 얻음

nDCG

$$

nDCG@K=\frac{DCG@K}{DCG_{ideal}@K}

$$

- $DCG_{ideal}$→ 아이템을 가장 이상적인 순위로 정렬했을 때의 DCG
- 실제 DCG를 이상적인 DCG로 나누어 정규화
- 0~1 범위의 값을 가지며 1에 가까울수록 이상적인 순위

계산 예시

사용자 행동에 따른 적합도 정의

- 클릭하지 않음 → 0
- 클릭함 → 1
- 구매함 → 2

실제 추천 순위가 `[0, 2, 0, 1, 0]`일 때

$$
DCG=0+\frac{2}{\log_2 2}+\frac{0}{\log_2 3}+\frac{1}{\log_2 4}+0=2.5

$$

이상적인 순위는 `[2, 1, 0, 0, 0]`이므로

$$
DCG_{ideal}=2+\frac{1}{\log_2 2}=3.0

$$

$$
nDCG=\frac{2.5}{3.0}\approx0.833

$$

특징

- 적합 여부뿐 아니라 적합도의 크기를 반영
- 상위에 배치된 아이템에 더 높은 가치를 부여
- 클릭과 구매 등 서로 다른 행동에 가중치를 부여할 수 있음
- 이상적인 순위와 비교하여 추천 결과의 품질 평가

핵심 → 사용자에게 가치가 높은 아이템을 얼마나 적절한 순위에 배치했는지 평가

## 3. 기타 평가 지표

지금까지 살펴본 지표는 주로 추천 결과의 정확도와 순위 품질을 평가하는 지표였음

그러나 실제 추천 시스템에서는 정확도뿐만 아니라 새로운 아이템을 추천하는지, 다양한 아이템을 제공하는지, 예상하지 못한 유용한 아이템을 발견하도록 돕는지도 중요함

### 3.1 카탈로그 커버리지 (Catalogue Coverage)

> 전체 아이템 중 실제로 추천된 아이템의 비율
> 

$$
Catalogue\ Coverage=\frac{|\hat I|}{|I|}

$$

- $\hat I$ → 실제로 추천된 아이템 집합
- $I$ → 전체 아이템 집합

예시

전체 영화가 1,000개이고, 그중 실제로 추천된 영화가 200개라면

$$

Catalogue\ Coverage=\frac{200}{1000}=0.2

$$

→ 카탈로그 커버리지 20%

특징

- 추천 시스템이 전체 아이템을 얼마나 폭넓게 활용하는지 평가
- 인기 아이템에만 추천이 집중되는 현상을 확인하는 데 활용
- 커버리지가 지나치게 낮으면 소수 아이템에 추천이 편중되었을 가능성이 있음

### 3.2 사용자 커버리지 (User Coverage)

> 전체 사용자 중 실제로 추천을 제공받은 사용자의 비율
> 

$$
User\ Coverage=\frac{|\hat U|}{|U|}

$$

- \ $\hat U$ → 실제로 추천이 수행된 사용자 집합
- $U$ → 전체 사용자 집합

예시

전체 사용자가 100명이고, 추천 결과를 받은 사용자가 80명이라면

$$
User\ Coverage=\frac{80}{100}=0.8

$$

→ 사용자 커버리지 80%

특징

- 추천 시스템이 얼마나 많은 사용자에게 추천을 제공하는지 평가
- 콜드 스타트 문제를 확인하는 데 활용 가능
- 신규 사용자에게 추천이 제대로 제공되지 않는 문제를 파악할 수 있음
- 날짜별 커버리지를 비교하여 시스템 오류나 추천 모델 업데이트 문제를 감지하는 데에도 활용

### 3.3 신규성 (Novelty)

> 추천 아이템이 사용자에게 얼마나 새로운 아이템인지를 평가하는 지표
> 

$$

Novelty(R)=\frac{\sum_{i\in R}-\log_2 p(i)}{|R|}

$$

- $R$  → 추천 순위
- $p(i)$ → 전체 사용자에게 아이템 \(i\)가 과거에 추천되었을 확률

특징

- 과거에 자주 추천된 아이템은 신규성이 낮음
- 상대적으로 추천된 적이 적은 아이템은 신규성이 높음
- 사용자가 기존에 접하지 못했던 아이템을 발견하도록 돕는지 평가

예시

- 영화 A → 대부분의 사용자에게 자주 추천된 인기 영화
- 영화 B → 과거에 추천된 빈도가 낮은 영화

→ 이 지표에서는 영화 B의 신규성이 더 높게 평가됨

단, 신규성이 높다고 해서 반드시 사용자에게 적합한 추천인 것은 아님

### 3.4 다양성 (Diversity)

> 하나의 추천 목록에 포함된 아이템들이 서로 얼마나 다른지를 평가하는 지표
> 

책에서는 추천 목록 내 아이템 간의 거리를 평균하여 다양성을 계산함

$$
Diversity(R)=
\frac{\sum_{i\in R}\sum_{j\in R\setminus\{i\}}sim(i,j)}
{|R|(|R|-1)}
$$

- $R$  → 추천 순위
- $sim(i,j)$ → 책의 정의에서는 아이템 \(i\)와 \(j\) 사이의 유사도 거리
- 아이템 간 거리가 클수록 다양성이 높아짐

예시

| 추천 결과 | 다양성 |
| --- | --- |
| 액션, 액션, 액션, 액션 | 낮음 |
| 액션, 코미디, SF, 다큐멘터리 | 상대적으로 높음 |

특징

- 비슷한 아이템만 반복적으로 추천하는 문제를 평가
- 다양한 장르나 특성의 아이템을 제공하는지 확인
- 추천 목록 내 아이템 간 차이를 측정하는 Intra-list Diversity에 해당

핵심 → 추천 결과가 얼마나 다양한 선택지를 제공하는지 평가

참고로 책의 수식에서는 `sim(i,j)`라는 기호를 사용하지만, 일반적인 유사도 점수와 달리 아이템 간 거리로 정의하고 있음

### 3.5 흥미로움 (Serendipity)

> 사용자가 예상하지 못했지만 실제로 유용하다고 느끼는 아이템을 추천하는 정도
> 

$$
Serendipity(R,u)=
\frac{|R_{unexp}\cap R_{useful}|}{|R|}

$$

- $R$ → 추천 목록
- $R_{unexp}$→ 사용자에게 의외성이 있는 아이템 집합
- $R_{useful}$ → 사용자에게 유용한 아이템 집합

예시

평소 액션 영화만 시청하던 사용자에게 다큐멘터리를 추천했는데, 사용자가 예상외로 만족한 경우

→ 예상하지 못한 추천이면서 실제로 유용했으므로 흥미로움이 높은 추천

특징

- 단순히 새로운 아이템을 추천하는 것과는 차이가 있음
- 예상하지 못한 아이템이면서 사용자에게 유용해야 함
- 추천 시스템이 새로운 관심사를 발견하도록 돕는지 평가

### 3.6 신규성, 다양성, 흥미로움 비교

| 지표 | 평가 관점 | 핵심 질문 |
| --- | --- | --- |
| 신규성 | 아이템이 얼마나 새로운가 | 자주 추천되지 않았던 아이템인가? |
| 다양성 | 추천 목록이 얼마나 다양한가 | 추천된 아이템들이 서로 다른가? |
| 흥미로움 | 예상 밖의 유용한 발견인가 | 예상하지 못했지만 만족스러운가? |

세 지표는 서로 연관되어 있지만 동일한 개념은 아님

예를 들어 새로운 영화 5개를 추천하더라도 모두 같은 장르라면 신규성은 높지만 다양성은 낮을 수 있음

또한 새로운 장르를 추천하더라도 사용자가 흥미를 느끼지 못한다면 흥미로움이 높다고 볼 수 없음

## 4. 평가 지표 선정 방법

> 추천 시스템의 평가 지표는 서비스의 목적과 사용자의 행동 의도에 따라 선택해야 함
> 

### 4.1 오프라인 평가 지표와 실제 서비스 성과

오프라인 평가에서 높은 성능을 보인 모델이 반드시 실제 서비스에서도 좋은 결과를 얻는 것은 아님

- 오프라인 평가 → Precision, Recall, MAP, nDCG 등으로 추천 모델의 성능을 측정
- 온라인 평가 → 실제 사용자 행동이나 비즈니스 지표를 통해 추천 효과를 확인

문제점

- 정확도가 높은 모델이 실제 구매율이나 클릭률까지 높인다는 보장은 없음
- 평가 데이터에서의 성능과 실제 사용자 행동 사이에 차이가 발생할 수 있음

개선 방향

- 서비스 목적에 맞는 오프라인 평가 지표 선정
- 정확도뿐 아니라 커버리지, 신규성, 다양성 등 다양한 지표를 함께 고려
- 실제 서비스의 온라인 지표와 오프라인 지표의 관계를 확인

### 4.2 사용자 행동 의도에 따른 평가 지표

책에서는 사용자의 행동 의도를 세 가지로 분류함

| 구분 | 사용자 의도 | 예시 |
| --- | --- | --- |
| 유도형 (Navigational) | 특정한 하나의 적합한 결과를 찾음 | 원하는 열차 시간표 검색 |
| 정보 수집형 (Informational) | 여러 결과에서 필요한 정보를 수집 | 여행 정보를 얻기 위한 검색 |
| 거래형 (Transactional) | 특정 행동을 수행하려는 목적 | 음식점 예약 |

① 유도형 (Navigational)

사용자가 원하는 결과를 하나 찾는 것이 중요하므로, 최초 적합 아이템이 얼마나 상위에 있는지 평가하는 지표가 적합함

- 이진 적합성 → Reciprocal Rank(MRR)
- 다중값 적합성 → ERR(Expected Reciprocal Rank)

② 정보 수집형 (Informational)

하나의 결과보다 여러 개의 적합한 아이템을 제공하는 것이 중요하므로, 추천 목록 전체의 품질을 평가하는 지표가 적합함

- 이진 적합성 → Average Precision(AP)
- 다중값 적합성 → nDCG

③ 거래형 (Transactional)

검색이나 추천 이후 실제 행동을 수행하는 것이 목적이므로, 클릭이나 구매, 예약 등 실제 행동과 관련된 지표를 고려해야 함

## 중요하게 본 내용

- 가장 기억에 남는 내용: 추천 시스템의 정확도가 높더라도 신규성이나 다양성이 낮으면 사용자에게 비슷한 아이템만 반복적으로 추천할 수 있다는 점
- 중요하다고 생각한 이유: 기존 평가 지표는 적합한 아이템을 얼마나 정확하게 추천했는지에 집중하지만, 실제 서비스에서는 새로운 아이템을 발견하거나 다양한 선택지를 제공하는 것도 사용자 경험에 영향을 줄 수 있기 때문
- 다른 주제와 연결되는 부분:  이전에 학습한 협업 필터링과 내용 기반 필터링의 특성을 평가 지표와 연결할 수 있음. 내용 기반 필터링에서는 사용자의 기존 취향과 유사한 아이템이 반복될 가능성이 있으므로 다양성이나 신규성을 함께 살펴볼 수 있음. 또한 협업 필터링에서도 인기 아이템에 추천이 집중될 수 있으므로 카탈로그 커버리지를 통해 추천 편중을 확인할 수 있음

## 질문 및 토론거리

- 이해가 어려웠던 부분: MRR과 MAP는 모두 추천 결과의 순위를 평가하는 지표인데, 최초 적합 아이템만 고려하는 MRR과 여러 적합 아이템을 고려하는 MAP를 실제 서비스에서 어떤 기준으로 구분하여 사용해야 하는지 이해하기 어려웠음
- 팀원들과 함께 이야기할 질문
    - 콜드 스타트 상황에서 사용자 커버리지가 낮게 나타난다면, 추천 모델을 개선하는 것과 인기 아이템 기반의 기본 추천을 제공하는 것 중 어떤 방법이 더 적절할까?
    **노시은**: 사용자 커버리지가 낮은 상태에서는 모델을 개선하는 데에 한계가 있기 떄문에 일단 인기 아이템 기반의 기본 추천을 제공하고 점차 추천 모델을 개선하는 게 나을 것 같다. 
    **이동민**: 인기 아이템 기반의 기본추천을 제공하는 게 적합해보인다. 콜드 스타트를 위한 모델을 따로 정비하거나 마련한다고 해도 소요가 크거나 의미가 없을 수 있다.
    **이윤성**: 콜드 스타트 상황에서는 초기 데이터가 부족할 뿐만 아니라 사용자 데이터를 적극적으로 수집해야 하는 타이밍이기 때문에, 인기 아이템 기본 추천 제공 후 사용자의 판단 및 데이터를 수집하여 그 경향성이나 오차를 발견하는 것이 더 적합해 보인다.
    **안현지:** 인기 아이템 기반의 기본추천을 제공하는 것이 적절할 것 같다. 콜드 스타트 상황에서는 사용자 데이터가 부족하기 때문에 모델의 성능을 올려도 한계가 있을 것 같다.
    - 오프라인 평가에서는 nDCG가 높은 모델이 실제 서비스에서는 클릭률이 낮게 나타난다면, 어떤 지표를 기준으로 모델을 선택하는 것이 좋을까?
    **노시은**: 사용자가 클릭하지 않는다면 무의미하기 때문에 실제 사용자의 행동을 반영하는 클릭률을 기준으로 삼아 모델을 선택하는 것이 좋을 것 같다. 
    **이동민**: 클릭 뿐만 아니라 머문 시간이나 다른 지표들도 인코딩해서 활용해볼 수 있을 것 같다.
    **이윤성**: 실제 서비스에서 오프라인에 비해 nDCG가 낮은 경우, 상단 노출이 잘 되지 않았을 확률이 높으므로, MRR값을 계산하여 그 값이 최적화된 모델을 선택한다.
    **안현지:** 실제 서비스 지표 클릭률을 기준으로 선택하는 것이 좋을 것 같다. 대신 왜 nDCG와 잘 안맞았는지 분석해서 다음부터는 클릭률과 잘 맞는 오프라인 지표를 선택해야 될 것 같다
- 새롭게 이해한 내용: MRR과 MAP는 모두 추천 순위를 평가하지만 사용자가 원하는 결과 하나를 찾는 상황인지 여러 결과를 탐색하는 상황인지에 따라 적절한 지표가 달라진다는 점을 이해함
- 수정하거나 추가할 내용
    - 추천 시스템의 평가 지표를 선정할 떄 정확도 뿐 아니라 사용자 행동 위도와 서비스 목표를 함꼐 고려해야 함을 추가
    - 콜드 스타트 상황에서 사용자 커버리지를 높이기 위한 기본 추천 제공 및 행동 데이터 수집 전략을 추가
