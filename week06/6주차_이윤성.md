## 내용 1 - 추천 시스템의 3가지 평가 방법

- **오프라인 평가(Offline Evaluation)**
    - 과거 사용자 행동 기록(서비스 로그)을 활용한 추천 모델 성능 평가
    - 평가 지표: RMSE, nDCG 등
    - 평가 방법: 시뮬레이션
    - 장점: 낮은 구현 비용, 풍부한 데이터, 안정적인 평가 결과
    - 단점: 실제 사용자 만족도 및 비즈니스 성과 반영의 한계
- **온라인 평가(Online Evaluation)**
    - 실제 서비스 환경에서 새로운 추천 모델을 사용자에게 적용하여 평가
    - 평가 지표: 클릭률(CTR), 매출, 지속률 등
    - 평가 방법: A/B 테스트, 인터리빙(Interleaving)
    - 장점: 실제 사용자 반응 및 비즈니스 성과 직접 측정
    - 단점: 높은 구현 비용, 사용자 만족도 하락 위험
- **사용자 스터디(User Study)**
    - 인터뷰 및 설문 조사를 통한 사용자 경험 평가
    - 평가 항목: 만족도, 유용성, 신선함 등
    - 장점: 사용자 의견과 정성적 피드백 수집
    - 단점: 주관적인 응답, 대표성 및 재현성 확보의 어려움

## 내용 2 - 모델 정확도 평가와 밸리데이션

- **모델 정확도 평가**
    - 과거 사용자 행동을 학습하여 새로운 사용자 행동을 예측하는 능력 평가
    - 학습하지 않은 데이터에 대한 일반화 성능 확인
    - 미지 데이터의 예측 정확도가 핵심
- **모델 밸리데이션(Model Validation)**
    - Train: 추천 모델 학습에 사용하는 데이터
    - Validation: 모델 성능 검증 및 하이퍼파라미터 조정에 사용하는 데이터
    - Test: 최종 모델의 일반화 성능을 평가하는 데이터
    - 일반적인 분할 비율: `6:2:2` 또는 `8:1:1`
    - Test 데이터는 최종 평가 전까지 튜닝에 사용하지 않는 것이 원칙
- **시계열 데이터 분할**
    - 시간 순서에 따라 Train → Validation → Test 분할
    - 과거 데이터를 학습하고 미래 데이터를 예측하는 방식
    - 미래 정보가 학습 과정에 포함되는 데이터 누수(Data Leakage) 방지

### 주요 평가 지표 및 수식

**① RMSE(Root Mean Squared Error)**

- 수식: `RMSE = √[Σ(실제 평점 - 예측 평점)² / N]`
- **N**: 평가 데이터 개수
- 실제 평점과 예측 평점 사이의 오차 측정
- RMSE가 낮을수록 높은 예측 정확도

**② nDCG(Normalized Discounted Cumulative Gain)**

- 수식: `nDCG@K = DCG@K / IDCG@K`
- **DCG@K**: 추천 순위를 고려한 관련성 점수
- **IDCG@K**: 이상적인 추천 순서에서의 최대 DCG
- **K**: 평가할 상위 추천 아이템 개수
- nDCG가 **1에 가까울수록 우수한 추천 순위**
- **Example**
    - 실제 영화 평점: 4.0점
    - 예측 영화 평점: 4.5점
    - 예측 오차: 0.5점
    - **RMSE**: 여러 영화의 **예측 오차를 종합**하여 평가
    - **nDCG**: **선호도가 높은** 영화를 추천 목록 **상위에 얼마나 잘 배치**했는지 평가

## 내용 3 - 모델 튜닝과 파라미터 최적화

- **모델 튜닝(Model Tuning)**
    - 추천 모델의 예측 성능 향상을 위한 파라미터 조정 과정
    - Validation 데이터의 평가 결과를 기반으로 최적의 설정 탐색
    - Test 데이터를 반복적으로 사용한 튜닝 지양
- **주요 튜닝 방법**
    - 수동 튜닝(Manual Tuning): 개발자가 직접 파라미터를 조정하며 성능 비교
    - 그리드 서치(Grid Search): 사전에 지정한 모든 파라미터 조합 평가
    - 베이즈 최적화(Bayesian Optimization): 이전 평가 결과를 활용한 효율적인 파라미터 탐색
    - 관련 라이브러리: Optuna, Hyperopt
- **Example**
    - 영화 추천 모델의 이웃 수 후보: `10, 20, 30`
    - **Validation 데이터**로 각 설정의 nDCG 측정
    - 가장 높은 성능을 보이는 설정 선택
    - 최종 Test 데이터로 모델의 일반화 성능 평가

## 중요하게 본 내용

- **가장 기억에 남는 내용:** 오프라인 평가에서 높은 정확도를 보인 추천 모델이 실제 서비스에서도 높은 사용자 만족도를 보장하지 않는다는 점
- **중요하다고 생각한 이유:** 추천 정확도뿐 아니라 사용자 경험과 실제 서비스 성과를 함께 고려해야 하기 때문
- **다른 주제와 연결되는 부분:** 그룹 영화 추천 시스템에서 nDCG로 추천 품질을 평가하고, 사용자 스터디로 그룹 구성원의 만족도를 검증하는 방식

## 질문 및 토론거리

- **이해가 어려웠던 부분:** Validation과 Test 데이터의 역할 차이 및 베이즈 최적화의 파라미터 탐색 원리
- **팀원들과 함께 이야기할 질문:** 그룹 영화 추천 시스템에서는 전체 추천 정확도와 개별 구성원의 만족도 중 어떤 요소를 더 중요하게 평가해야 할까?
**김민서**: 개별 구성원의 만족도보다는 모든 팀원의 취향을 아우를 수 있는 전체 추천 정확도를 더 중요하게 평가해야 된다고 생각한다
**노시은**: 그룹 영화 추천 시스템에 보통 가입하는 이유는 정확한 추천을 받으려고 하기보다 다함께 즐기기 위함이기 때문에 개별 구성원의 만족도가 좀 높아도 괜찮을 것 같다. 
**안현지**:  개별구성원의 만족도를 중요하게 봐야할 것 같다. 영화를 다같이 보기 때문에 한명이라도 불호하는 영화가 있으면 만족도가 크게 떨어질 것 같다.
**이동민**: 개별 구성원의 만족도를 우선시하는 것이 중요하다. 만약 1점의 영화라고 해도 개별 구성원 전원이 5점이라고 했을때 그 집단에 있어서는  추천할만한 영화가 된다. 그렇게 추려진 데이터들에 다시 전체평가 요소를 더하는 것도 좋을 것 같다.

## 스터디 후 보완

- **새롭게 이해한 내용:** 추천 시스템 평가는 오프라인 정확도 측정뿐 아니라 실제 사용자 반응과 만족도 검증까지 포함하며, Train·Validation·Test 데이터 분리는 신뢰성 있는 모델 평가의 핵심
- **수정하거나 추가할 내용:** RMSE와 nDCG의 적용 상황 비교, Precision@K·Recall@K 지표 학습, 그룹 추천 시스템에 적합한 평가 방법 설계
