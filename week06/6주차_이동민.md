- 이 범위를 맡은 이유 또는 연결되는 내용: 지난주에는 추천 모델의 학습과 평가에 활용할 사용자 행동 로그를 살펴보았다. 이번에는 수집한 로그를 바탕으로 추천 시스템의 변경이 실제 사용자에게 도움이 되었는지 판단하는 방법을 정리했다. 모델의 예측 성능뿐 아니라 사용자 행동과 서비스 전체에 미치는 영향을 확인하는 과정으로 연결된다.

## 배운 내용 정리

### 온라인 평가가 필요한 이유

오프라인 평가는 실제 사용자에게 영향을 주지 않고 여러 모델을 비교할 수 있다는 장점이 있다. 하지만 저장된 데이터에서 좋은 결과를 얻었다고 해서 실제 서비스에서도 같은 효과가 나타나는 것은 아니다. 추천 상품의 이미지 크기나 배치처럼 화면 구성까지 바뀌는 경우에는 사용자가 어떻게 반응할지 기존 데이터만으로 판단하기 어렵다.

온라인 평가는 변경한 시스템을 실제 사용자에게 제공하고, 그 결과로 나타나는 행동을 관찰하는 방법이다. 따라서 추천 모델의 성능을 확인하는 것에서 더 나아가 **변경 사항이 실제 서비스의 목표 달성에 기여하는지** 평가할 수 있다.

### A/B 테스트는 가설과 판단 기준을 먼저 정하는 과정이다

A/B 테스트는 사용자를 무작위로 나누고, 기존 기능을 제공하는 대조군과 변경한 기능을 제공하는 실험군의 결과를 비교한다. 두 집단의 조건을 최대한 비슷하게 맞추면 관찰된 차이가 변경 사항에서 비롯되었는지 판단하기 쉬워진다.

테스트를 시작하기 전에는 무엇을 바꾸고 어떤 효과를 기대하는지 구체적으로 정해야 한다.

| 항목 | 추천 서비스에서 생각해 본 예 |
| --- | --- |
| 배경 | 사용자가 관심 있는 상품을 찾기까지 여러 페이지를 탐색한다. |
| 변경 사항 | 첫 화면에 새로운 개인화 추천 알고리즘을 적용한다. |
| 대상 사용자 | 기존 구매 이력이 있는 사용자 |
| 지표 목표 | 추천을 통해 상품을 구매한 사용자의 비율을 높인다. |
| 비즈니스 목표 | 사용자가 원하는 상품을 쉽게 찾도록 하여 구매와 재방문으로 이어지게 한다. |

이렇게 가설을 문서로 남기면 실험이 끝난 뒤 유리한 지표만 골라 성공이라고 해석하거나, 처음에 정한 목표를 바꾸는 일을 줄일 수 있다. 팀원들도 같은 기준으로 실험 결과를 판단할 수 있다.

실제 적용은 적은 수의 사용자부터 시작해 기능과 로그 수집이 정상적으로 동작하는지 확인한 뒤, 평가에 필요한 규모로 확대하는 방식으로 진행한다.

### A/B 테스트에서는 비교 조건과 로그 수집 방식도 중요하다

사용자를 두 집단으로 나누었다는 사실만으로 공정한 비교가 보장되지는 않는다.

- **그룹 편향:** 한쪽 집단에 원래 클릭을 많이 하는 사용자가 몰려 있다면, 클릭 수의 차이를 추천 모델의 효과로 해석하기 어렵다. 같은 기능을 두 집단에 제공하는 A/A 테스트로 집단 간 차이나 실험 체계의 문제를 점검할 수 있다.
- **학습 로그의 혼합:** 실험 중 발생한 행동 로그를 모델이 다시 학습한다면, 각 모델이 어떤 조건에서 생성된 로그를 학습했는지 살펴봐야 한다. 서로의 로그가 섞인 상태에서 얻은 결과가 전체 사용자에게 배포한 뒤에도 유지된다고 단정하기 어렵다.
- **집계 기간:** 사용자가 새로운 기능에 일시적으로 관심을 보일 수 있다. 특정 요일이나 계절에만 나타나는 효과도 있으므로 짧은 기간의 결과를 장기적인 효과로 해석하지 않도록 주의해야 한다.

결국 A/B 테스트에서는 결과 지표뿐 아니라 **사용자 배정, 학습 데이터, 측정 기간이 비교에 어떤 영향을 주었는지** 함께 확인해야 한다.

### OEC 지표와 가드레일 지표는 서로 다른 역할을 한다

**OEC 지표**는 실험의 성공 여부를 최종적으로 판단하는 기준이다. 단기간에 측정할 수 있으면서도 서비스의 장기적인 목표와 연결되어야 한다.

사용자 관점에서 지표를 생각하는 방법으로는 HEART가 있다.

| 관점 | 살펴보는 내용 |
| --- | --- |
| Happiness | 서비스에 대한 만족도와 사용 경험 |
| Engagement | 사용 빈도와 상호작용의 깊이 |
| Adoption | 새로운 사용자가 서비스를 사용하기 시작하는 정도 |
| Retention | 사용자가 시간이 지난 뒤에도 계속 이용하는 정도 |
| Task success | 원하는 일을 얼마나 쉽고 성공적으로 완료하는지 |

**가드레일 지표**는 변경 과정에서 나빠지지 않아야 하는 조건을 확인한다. 예를 들어 추천을 통한 구매 비율이 높아졌더라도 응답 시간이 길어지거나 오류가 늘어난다면 그대로 적용하기 어렵다.

또한 개인화 추천 영역의 클릭 수가 증가하면서 다른 추천 영역의 클릭 수는 감소할 수 있다. 따라서 특정 기능의 성과만 보는 것이 아니라 서비스 전체에서 얻은 효과와 손실을 함께 판단해야 한다.

### 좋은 지표는 변화를 감지하면서도 결과를 믿고 해석할 수 있어야 한다

교재에서는 좋은 지표의 특성을 STEDI로 설명한다.

| 특성 | 이해한 내용 |
| --- | --- |
| 감도 | 실제 효과가 있을 때 이를 잘 발견해야 한다. 변화가 없을 때도 쉽게 흔들리는 지표와는 구분해야 한다. |
| 신뢰성 | 로그 누락, 수집 오류, 봇의 접근 등으로 결과가 왜곡되지 않아야 한다. |
| 효율성 | 결과를 얻는 데 필요한 시간과 비용이 적절하고, 반복해서 측정할 수 있어야 한다. |
| 디버깅 가능성과 액션 가능성 | 이상이 생겼을 때 원인을 추적하고 다음 행동을 결정하는 데 도움이 되어야 한다. |
| 해석 가능성과 방향성 | 수치의 의미가 명확하고, 지표가 좋아지는 방향이 서비스 목표의 개선과 연결되어야 한다. |

특히 **숫자가 크게 변했다는 사실과 실제로 좋은 변화가 일어났다는 판단은 다르다**는 점이 중요했다. 클릭률이 갑자기 높아졌다면 추천이 좋아졌을 수도 있지만, 로그 중복이나 측정 오류가 원인일 수도 있다.

또한 장기적인 목표를 직접 확인하려면 시간이 오래 걸릴 수 있으므로, 더 빨리 측정할 수 있는 대리 지표를 활용하기도 한다. 다만 대리 지표가 좋아지는 것이 실제 목표의 개선과 연결되는지 확인해야 한다.

### 인터리빙은 여러 추천 순위를 섞어 상대적인 선호를 비교한다

A/B 테스트는 사용자 집단을 나누어 서로 다른 결과를 보여준다. 반면 인터리빙은 두 모델의 추천 순위를 하나의 목록으로 섞어서 보여주고, 사용자가 선택한 항목을 바탕으로 어느 모델의 순위가 더 선호되는지 평가한다.

두 순위를 비교하는 방법을 인터리빙, 세 개 이상의 순위를 비교하는 방법을 멀티리빙이라고 한다. 여러 후보 모델을 빠르게 비교하고, 이후 A/B 테스트를 진행할 후보를 좁히는 데 활용할 수 있다.

| 구분 | A/B 테스트 | 인터리빙 |
| --- | --- | --- |
| 비교 방식 | 사용자 집단을 나누어 서로 다른 결과를 제공 | 여러 모델의 추천 순위를 섞어 하나의 목록으로 제공 |
| 주요 평가 대상 | 추천 모델과 UI 등 서비스의 변경 사항 | 추천 모델이 만든 순위의 상대적인 선호 |
| 평가 효율 | 충분한 사용자와 관찰 기간이 필요 | 순위 비교에서 적은 사용자로 차이를 발견하는 데 유리 |
| 구현 부담 | 상대적으로 낮음 | 순위를 섞고 클릭의 기여도를 판단하는 과정이 필요 |

대표적인 방법으로는 TDM, PM, OM, PPM이 있다. TDM은 각 순위에서 아직 선택되지 않은 항목을 번갈아 뽑는 방식으로 이해할 수 있다. PM은 확률적으로 항목을 선택하고, OM은 후보 목록의 출력 확률을 최적화한다. PPM은 항목 간 선호 관계를 이용하며 이론적 성질을 보장하지만 구현과 집계가 복잡하다.

따라서 평가 효율뿐 아니라 구현 비용도 고려해야 한다. 인터리빙으로 순위 후보를 비교하더라도, 최종 변경이 구매나 재방문 같은 서비스 목표에 도움이 되는지는 별도로 확인할 필요가 있다.

## 중요하게 본 내용

- 가장 기억에 남는 내용: 특정 추천 영역의 지표가 좋아졌더라도 서비스 전체의 성과가 좋아졌다고 단정할 수 없다는 점이다.
- 중요하다고 생각한 이유: 개인화 추천 영역에서 클릭이 늘어난 만큼 다른 영역의 클릭이 줄었다면, 사용자의 행동 위치만 바뀌었을 가능성이 있다. 기능을 개선했다는 결론을 내리려면 OEC 지표와 가드레일 지표를 함께 살펴봐야 한다.
- 다른 주제와 연결되는 부분: 지난주에 다룬 사용자 행동 로그와 연결된다. 어떤 모델이 어느 위치에 노출한 항목에서 행동이 발생했는지 남겨야 실험 결과를 해석할 수 있다. 밴딧 알고리즘과도 연결되지만, 좋은 선택에 노출을 늘리는 목적과 변경의 효과를 비교·검증하는 목적을 구분해서 생각해야 한다.

## 질문 및 토론거리

- 이해가 어려웠던 부분: 인터리빙에서 클릭한 항목이 두 모델에 공통으로 포함되어 있거나, 더 높은 위치에 배치되어 클릭된 경우에 각 모델의 기여도를 어떻게 판단하는지 궁금했다. 단순히 어느 모델이 가져온 항목인지 세는 것만으로는 공정한 비교가 어려울 것 같다.
- 팀원들과 함께 이야기할 질문:
    - 새로운 추천 모델의 클릭률은 높아졌지만 구매율과 재방문율은 그대로라면, 어떤 추가 근거가 있어야 적용을 결정할 수 있을까?
    **김민서**: 클릭율이 높아졌다는 것 만으로는 바로 새로운 모델은 적용하기는 어렵고 클릭이 실제 구매나 만족도로 이어졌는지를 봐야할 것 같다
    **노시은**: 사용자의 만족도나 체류시간 등 다른 기준들도 함께 분석하면 적용을 결정할 수 있을 것 같다. 
    **안현지**:  클릭률만 오른 것은 추천이 사용자를 끌어들였지만 실제로 원하던 아이템은 아니었을 가능성이 있다. 그래서 클릭 이후의 이탈률이나 체류 시간 등을 근거로 적용을 결정할 수 있을 것 같다.
    **이윤성**: 대상 사용자와 지표 목표를 재확인하고, 이를 바탕으로 '기존 구매 이력' 등의 추가 근거 데이터를 활용하여 그 연관성을 분석해야 할 필요성이 있다.
    - 인터리빙에서 선호된 모델이 A/B 테스트에서는 더 낮은 구매율을 보인다면, 두 결과의 차이를 어떤 순서로 분석해야 할까?
    **김민서**: 일단 두 결과가 통계적으로 신뢰할 수 있는지를 확인하고 실험조건에 차이가 있었는지를 봐야 할 것 같다. 후에는 왜 차이가 있었는지 이유를 분석해야 할 것 같다.
    **노시은**: A/B 테스트는 실제 구매로 이어지는지를 확인할 수 있기 때문에 서비스의 최종 목표인 구매율을 기준으로 우선적으로 모델을 선택하는 것이 좋을 것 같다.
    **안현지**: 클릭이 구매로 이어지지 않은 이유를 찾으면 좋을 것 같다. 그리고 두 모델이 상위에 올린 아이템의 성격을 비교해서 클릭은 잘 되지만 구매로는 이어지지 않는 아이템 추천을 분석하면 될 것 같다.
    **이윤성**: 인터리빙이 상대적인 데이터인 만큼, A/B테스트에서 구매율 관련 데이터를 먼저 확인하고, 인터리빙을 바탕으로 확인하는 절차로 가야 할 것 같다.

## 스터디 후 보완

- 새롭게 이해한 내용: 클릭률 상승은 사용자의 관심을 끌었다는 신호이지만, 구매나 만족도 향상까지 의미하지는 않는다는 점을 더 구체적으로 이해했다. 클릭 이후의 이탈률, 체류 시간, 구매 전환 등을 함께 살펴봐야 사용자가 원하는 아이템을 찾았는지 판단할 수 있다. 또한 인터리빙과 A/B 테스트의 결과가 다를 때는 두 실험이 측정하는 대상이 다르다는 점을 고려해야 한다. 순위에 대한 상대적인 선호와 실제 구매 성과는 다를 수 있으므로, 결과의 신뢰성과 실험 조건을 먼저 확인한 뒤 서비스 목표를 기준으로 해석해야 한다.
- 수정하거나 추가할 내용:  클릭률만으로 추천 모델의 적용 여부를 판단하지 않도록, 추천 노출부터 클릭·이탈·구매까지 이어지는 과정을 함께 분석하는 내용을 추가하고 싶다. 체류 시간 역시 길어졌다는 이유만으로 긍정적으로 보기보다, 관심 있게 살펴본 것인지 원하는 상품을 찾기 어려웠던 것인지 구분해야 한다. 인터리빙과 A/B 테스트의 결과가 엇갈리는 경우에는 결과의 신뢰성 확인 → 사용자 구성과 실험 조건 비교 → 클릭 이후 행동 분석 → 상위 추천 아이템의 특성 비교 순서로 원인을 점검하도록 보완할 예정이다.
