## 내가 맡은 범위

- 담당 절·주제: 7.4 사용자 스터디를 통한 평가 ~ 7.5 정리
- 이 범위를 맡은 이유 또는 연결되는 내용: 실제 사용자의 경험을 통해 추천 시스템을 평가하는 방법을 이해하는 장이다. 사용자 스터디의 설문 조사 예시를 살펴보며 추천 시스템의 사용자 만족도와 신뢰도 등을 평가하는 방법을 알아볼 수 있다.

## 배운 내용 정리

### 1. 사용자 스터디를 통한 평가 (7.4)

- **개념:** 실제 사용자를 대상으로 직접 인터뷰나 설문 조사를 진행하여 추천 시스템에 대한 만족도를 평가
- **특징**
    - 실제 사용자에게 직접 의견을 수집
    - 추천 시스템의 기능뿐만 아니라 사용자 경험을 평가할 수 있음
    - 정성적인 관점에서 기존 평가 방법을 보완

### 2. 조사 설계 (7.4.1)

- **개념:** 사용자 스터디를 수행하기 전에 평가 목적에 맞게 참가자와 조사 방법 등을 계획하는 과정
- **주요 고려 사항:** 참가자 선정, 참가자 수, 조사 시점, 피험자 내 측정·피험자 간 측정

#### 2-1. 참가자 선정

- **개념:** 사용자 스터디의 목적에 적합한 실제 사용자를 조사 대상으로 선정하는 과정
- **특징**
    - 실제 서비스 사용자와 가까운 사람으로 선정하는 것이 좋음
    - 일반 사용자가 아닌 개발자를 대상으로 조사하면 부족한 기능이 파악됨
    - 다양한 유형의 사용자를 조사해야 여러 관점의 의견을 수집할 수 있음
- **고려해야 할 정보**
    - 전문 지식 수준(초급, 중급, 상급)
    - 서비스 사용 빈도(전체 사용 횟수, 특정 기간의 사용 횟수)
    - 사용자 속성 정보(성별, 나이, 거주 지역, 가족 구성 등)

⇒ 조사 목적에 맞는 참가자를 선정해야 실제 사용자에게 적용할 수 있는 평가 결과를 얻을 수 있음

- **샘플링:** 전체 조사 대상 중에서 실제 사용자 스터디에 참여할 일부 사용자를 선정하는 방법
- **대표 방법**
    - **단순 무작위 추출법:** 모집단에 포함된 모든 사용자가 같은 확률로 선택되도록 무작위로 추출하는 방법
    - **계통적 추출법:** 사용자에게 번호를 부여한 뒤 일정한 간격을 두고 추출하는 방법
    - **층화 추출법:** 나이, 성별 등 사용자 특성에 따라 집단을 나눈 뒤 각 집단에서 무작위로 추출하는 방법
    - **임의 추출법:** 조사에 참여하고 싶은 사람에게 참여하도록 하는 방법

⇒ 평가 목적에 따라 적절한 샘플링 방법을 선택해야 함

#### 2-2. 참가자 수

- **개념:** 조사 목적과 허용 가능한 오차에 따라 필요한 참가자 수를 결정하는 과정
- **특징**
    - 사용성 문제를 발견하는 것이 목적이라면 비교적 적은 참가자로도 여러 문제를 찾을 수 있음
    - 다양한 측면의 피드백을 수집하려면 더 많은 참가자가 필요할 수 있음
    - 초기에는 소수의 참가자로 주요 문제를 발견하고, 시스템이 완성되어 갈수록 참가자를 늘려 작은 문제까지 확인하는 방법이 이상적임

#### 2-3. 조사 시점

- **개념:** 사용자 스터디를 어느 시점에 수행할 것인지 결정하는 과정
- **특징**
    - 신규 서비스를 개발할 때는 핵심 기능을 최소한으로 구현한 후 조사할 수 있음
    - 서비스의 전체 기능이 완성된 후에도 조사 가능
    - 성숙한 서비스에서도 정기적인 사용자 조사를 수행하는 것이 좋음
- **필요한 이유**
    - 기능별 개선이 전체 사용자 만족도 향상으로 이어지지 않을 수 있음
    - 시간이 지나면서 사용자의 만족도나 요구가 달라질 수 있음

⇒ 사용자 스터디는 서비스 개발 초기뿐만 아니라 운영 과정에서도 지속적으로 활용할 필요가 있음

#### 2-4. 피험자 내 측정과 피험자 간 측정

- **피험자 내 측정:** 한 참가자에게 여러 평가를 수행하게 하고 그 결과를 비교하는 방법
- **피험자 간 측정:** 서로 다른 참가자들의 평가 결과를 비교하는 방법

**피험자 내 측정의 특징**

- 참가자 사이의 특성 차이를 고려하지 않아도 됨
- 비교적 적은 참가자로 평가 가능
- 여러 평가를 순서대로 진행하면서 학습이나 피로가 발생할 수 있음 (캐리 오버 효과)
- 평가 순서를 무작위로 바꾸는 방법을 통해 순서에 따른 영향을 줄일 수 있음 (카운터 밸런스)

**피험자 간 측정의 특징**

- 참가자의 나이나 성숙도 등 특성에 따라 서로 다른 집단을 비교할 수 있음
- 피험자 내 측정보다 캐리 오버 효과가 작음
- 참가자 사이의 차이로 인해 결과의 분산이 커질 수 있어 더 많은 참가자가 필요함

| 구분 | 피험자 내 측정 | 피험자 간 측정 |
| --- | --- | --- |
| 비교 대상 | 동일한 참가자의 여러 평가 | 서로 다른 참가자의 평가 |
| 참가자 수 | 비교적 적은 수로 가능 | 상대적으로 많은 수 필요 |
| 장점 | 개인 차이의 영향 감소 | 캐리 오버 효과가 작음 |
| 단점 | 학습 및 피로의 영향 발생 | 개인 차이로 인한 분산 증가 |
| 고려 사항 | 평가 순서 조정 | 참가자 집단 간 차이 |

### **3. 설문 조사 예 (7.4.2)**

- **개념:** 설문 조사를 통해 사용자의 경험과 만족도를 평가하는 방법
- **대표 예시:** ResQue(사용자 중심 추천 시스템 평가 프레임워크)
- **특징**
    - 4가지 대항목으로 시스템 평가
    - 각 질문에 1점(전혀 찬성하지 않음)~5점(강하게 찬성함)까지 응답

**3-1. 시스템 품질**

- **개념:** 사용자가 느끼는 추천 시스템의 품질 평가
- **평가 요소:** 정확성, 신선함, 다양성, 매력 등
- **예시:** 추천된 아이템에 흥미를 느낀다

**3-2. 사용자의 신념**

- **개념:** 추천 시스템이 편리하고 유용하다고 느끼는지 평가
- **평가 요소:** 사용 용이성, 유용성, 제어 가능성
- **예시:** 추천 시스템은 나에게 이상적인 아이템을 찾는 것을 효과적으로 도왔다.

**3-3. 사용자의 태도**

- **개념:** 추천 시스템에 대한 만족도와 신뢰도 평가
- **평가 요소:** 전체 만족도, 신뢰성
- **예시:** 추천 시스템에 전체적으로 만족한다.

**3-4. 행동 의도**

- **개념:** 추천 시스템 이용 후 사용자의 행동 의향 평가
- **평가 요소:** 시스템 사용, 상품 구입, 서비스 지속, 주변 추천
- **예시:** 추천 시스템을 다시 사용하고 싶다.

⇒ ResQue는 **시스템 품질, 사용자의 신념, 사용자의 태도, 행동 의도**를 통해 추천 정확도뿐만 아니라 사용자 경험과 만족도를 종합적으로 평가하는 방법

### 4. 정리 (7.5)

- **주요 내용**
    - 추천 시스템 평가는 오프라인 평가, 온라인 평가, 사용자 스터디 등 다양한 방법으로 수행할 수 있음
    - 각 평가 방법은 서로 다른 역할과 한계를 가짐
    - 사용자 스터디를 통해 실제 사용자의 만족도와 경험을 파악할 수 있음
    - 추천 시스템의 정확한 지표 측정이 지속적인 서비스 개선과 건전한 성장으로 이어질 수 있음

## 중요하게 본 내용

- 가장 기억에 남는 내용: 추천 시스템은 단순히 추천 정확도가 높다고 해서 사용자에게 좋은 평가를 받는 것이 아니라는 점이다. 사용 편의성, 만족도 등을 함께 평가해야 한다.
- 중요하다고 생각한 이유: 앞에서는 추천 시스템의 성능을 정확도로 평가한다고 생각했지만, 실제 서비스에서는 사용자가 어떻게 느끼는지도 중요하다는 것을 알게 되었다.
- 다른 주제와 연결되는 부분: 오프라인 평가에서는 추천 모델의 성능을 확인하고, 온라인 평가에서는 실제 서비스에서 나타나는 사용자 행동을 분석한다면, 사용자 스터디에서는 사용자가 추천 시스템을 어떻게 느끼는지 직접 확인할 수 있다.

## 질문 및 토론거리

- 이해가 어려웠던 부분:  캐리 오버 효과가 실제 평가 결과에 어떤 영향을 미치는지 잘 와닿지 않는다. 같은 참가자가 여러 추천 시스템을 평가할 때 학습이나 피로에 의한 영향을 카운터 밸런스로 얼마나 줄일 수 있는지 더 알아보고 싶다.
- 팀원들과 함께 이야기할 질문: 추천 정확도가 높은 시스템과 추천 결과의 다양성이나 신선함이 높은 시스템 중 사용자의 만족도가 더 높은 시스템을 선택하려면 어떤 기준으로 평가해야 할까?
    - **이윤성:** 단기적인 데이터 수집 및 정확성이 좀 더 중요한 목적의 추천 시스템일 경우 정확도가 높은 시스템, 다양한 범위/아이템을 고루 추천하는 것이 목적인 시스템의 경우 추천 결과의 다양성/신선함이 높은 시스템을 선택하는 등 그 목적에 따라 유연하게 결정해야 할 것 같다.
    - **이동민:** 전체적인 사용자에 대한 만족도는 물론 정확도가 높은 시스템이 좋겠지만, 사용자를 오래 붙잡아두기 위해서는 다양성이나 신선함이 높은 추천에 대해 꾸준히 자리를 할당해주는 것이 필요하다.
    - **김민서:** 사용자가 시스템을 방문하는 목적에 따라 가중치가 달라질 것 같다.
    - **안현지:** 정확도와 다양성 둘은 측정하는 것이 달라서 수치로 직접 비교하기는 어려우니까 온라인의 경우에선 재방문율과 같은 기준으로 장기적인 만족도를 확인하면 좋을 것 같다.

## 스터디 후 보완

- 새롭게 이해한 내용: 추천 시스템은 정확도뿐만 아니라 신규성, 다양성, 흥미로움 등 다양한 관점에서 평가해야 한다는 점을 새롭게 알게 되었다. 또한 사용자의 행동 의도와 서비스 목적에 따라 적절한 평가 지표를 선택하는 것이 중요하다는 것을 배웠다.
- 수정하거나 추가할 내용: 사용자 스터디에서는 참가자의 주관적인 응답이 결과에 영향을 미칠 수 있으므로, 설문 문항을 명확하게 구성하고 응답 편향을 줄이는 과정이 필요하다고 생각한다. 또한 설문 조사뿐만 아니라 실제 사용 과정을 관찰하는 방법도 함께 활용하면 더 구체적인 문제점을 발견할 수 있을 것 같다.
