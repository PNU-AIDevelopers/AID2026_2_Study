📚 스터디 진행상황
이번 주에는 팀원들과 모여 개인정보 자동 탐지·마스킹 서비스인 SafePrompt의 개발 계획을 논의했습니다. 지난주에 정한 역할 분배 계획을 바탕으로 프로젝트에 필요한 업무를 네 파트로 나누고, 각 파트의 책임과 주차별 진행 순서를 정리했습니다.
진행 내용
- 프로젝트 목표 구체화: 사용자가 LLM에 문장을 입력하기 전에 개인정보를 탐지하고, 사용자가 확인·선택한 정보를 가리는 서비스로 방향 정리
- 기본 구현 범위 설정: PERSON·PHONE·EMAIL 세 유형을 우선 대상으로 정하고, 개인정보 탐지 → 사용자 검토·선택 → 마스킹 → LLM 전달 → 응답 표시 흐름 설계
- 데이터 및 모델 계획: BC카드 공개 개인정보 데이터셋을 활용하고, Transformer 기반 NER 모델의 학습과 평가에 필요한 작업 정리
- 탐지 방식 설계: 문맥을 활용하는 NER 모델과 전화번호·이메일 패턴을 찾는 Regex를 함께 사용하고, 중복되는 탐지 결과를 병합하는 방식 계획
- 역할 및 일정 정리: A·B·C·D 파트별 개발 업무, 필요한 학습 내용, 파일 전달 시점과 협업 방식 정리
👥 팀원별 활동
팀원별로 다음과 같이 역할을 나누고, 각 파트의 작업 범위와 연결 관계를 함께 검토했습니다.
파트	담당 업무 및 활동 계획
A (마야) — 데이터 전처리·평가	데이터셋 구조 확인, 개인정보 위치와 토큰 라벨 정렬, 학습·평가 데이터 분리, Precision·Recall·F1 평가 및 오류 분석
B (신민영) — Transformer NER 모델	모델·Tokenizer 검토, 토큰 분류 모델 학습, 개인정보 위치·유형을 반환하는 추론 기능 구현
C (박세홍) — Regex·Hybrid 탐지	전화번호·이메일 정규표현식 작성, NER·Regex 결과 병합, 중복·충돌 처리
D (박근영) — 마스킹·서비스	Streamlit 화면 구성, 사용자 검토·선택 기능, Placeholder 마스킹, LLM API 연동

💬 스터디 회고
- 좋았던 점: 프로젝트를 네 파트로 나누면서 각자 준비할 내용과 다른 파트에 전달해야 할 결과물을 구체적으로 정리할 수 있었습니다.
- 어려웠던 점: 데이터 전처리, 모델 학습, 탐지 결과 병합, 서비스 구현이 서로 연결되어 있어 업무 경계와 개발 순서를 맞추는 데 논의가 필요했습니다.
- 개선할 점: 각 파트에서 사용하는 개인정보 라벨과 결과 형식을 미리 통일하고, 실제 모델이 준비되기 전에는 가상 예시로 기능을 확인하며 개발을 진행하기로 했습니다.
📌 다음 주 계획
1. A (마야): BC카드 데이터셋을 불러와 원문·개인정보 위치·라벨 구조를 확인하고 전처리 방향을 정리한다.
2. B (신민영): NER 모델 후보와 Tokenizer 구조를 살펴보고 토큰 분류 학습 방식을 공부한다.
3. C (박세홍): 전화번호·이메일 Regex와 탐지 위치를 나타내는 Span 개념을 공부하고 테스트 예시를 준비한다.
4. D (박근영): Streamlit과 Placeholder 마스킹의 기본 개념을 공부하고, Streamlit을 설치해 텍스트 입력창과 실행 버튼으로 기본 화면을 구성한다.
5. 공통: PERSON·PHONE·EMAIL 라벨과 모듈별 입력·출력 형식을 맞추고, GitHub와 Notion에 진행 내용을 공유한다.
6. 스터디 발표: 각자 담당 파트에 필요한 개념과 기술을 공부하고 발표 자료를 준비한다. 다음 스터디에서 학습한 내용과 프로젝트에 적용할 방법을 발표하고, 질의응답을 통해 서로 공유한다.
