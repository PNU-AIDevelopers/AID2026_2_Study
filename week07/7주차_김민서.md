## **배운 내용 정리**

추천 시스템은 단순히 사용자가 구매하거나 소비할 가능성이 높은 아이템을 추천하는 것뿐만 아니라, 추천으로 인해 발생하는 실질적인 효과와 서비스 도메인별 특성을 고려해야 함

# **1. 업리프트 모델링(Uplift Modeling)**

> 추천을 하지 않았을 때와 비교하여 추천으로 인해 추가적으로 발생한 효과를 측정하고 예측하는 방법
> 

### **1.1 기존 추천 시스템의 한계**

기존 전자상거래 추천 시스템은 추천을 통한 상품 구매 확률을 최대화하는 것을 목적으로 함

- 사용자가 구매할 가능성이 높은 상품을 추천함
- 추천 이후 구매가 발생하면 추천이 성공했다고 판단할 수 있음
- 하지만 추천하지 않아도 구매했을 상품인지 구분하기 어려움
- 추천 시스템의 실제 효과보다 성과가 과대평가될 수 있음

**ex) 생수 추천**

사용자가 정기적으로 생수를 구매한다고 가정

- 생수를 추천함 → 생수 구매
- 생수를 추천하지 않음 → 생수 구매

추천을 통해 구매가 발생했지만, 실제로 추천이 구매 여부에 영향을 미치지는 ❌

⇒ 단순히 구매 확률을 높이는 것이 아니라 **추천으로 인해 새롭게 발생하는 구매를 증가시키는 것이 중요함**

### **1.2 업리프트 관점에서의 구매 패턴**

![image.png](7%EC%A3%BC%EC%B0%A8%20%C2%B7%20%EA%B9%80%EB%AF%BC%EC%84%9C/image.png)

| 유형 | 특징 | 예시 |
| --- | --- | --- |
| TU | 추천해야 구매함 | 추천을 통해 새로운 상품을 발견하고 구매 |
| FU | 추천하지 않아도 구매함 | 정기적으로 구매하는 생필품 |
| TD | 추천하면 오히려 구매하지 않음 | 과도한 추천으로 구매 의욕 감소 |
| FD | 추천 여부와 관계없이 구매하지 않음 | 관심 없는 상품 |

⇒ 업리프트 모델링에서는 **TU의 비율을 높이고 TD의 발생을 줄이는 것이 중요함**

### **1.3 Uplift Score**

> 추천했을 때의 평균 구매 확률과 추천하지 않았을 때의 평균 구매 확률의 차이
> 

$$
\begin{aligned}
\text{Uplift Score} =\;&P(Y=1\mid do(T=1))\\
&-P(Y=1\mid do(T=0))
\end{aligned}
$$

- T → 추천 수행 여부
- Y → 구매 발생 여부
- Uplift Score > 0 → 추천이 구매에 긍정적인 영향을 미침
- Uplift Score = 0 → 추천에 의한 순효과가 없음
- Uplift Score < 0 → 추천이 구매에 부정적인 영향을 미침

**ex) 상품 A와 상품 B의 추천 효과 비교**

![image.png](7%EC%A3%BC%EC%B0%A8%20%C2%B7%20%EA%B9%80%EB%AF%BC%EC%84%9C/image%201.png)

개념 이해를 위한 가상의 구매 확률

- 기존 추천 시스템 → 구매 확률이 80%인 상품 A를 우선 추천
- 업리프트 모델링 → 추천으로 인한 구매 확률 증가량이 30%p인 상품 B를 우선 추천

⇒ 구매 확률이 높다고 해서 추천의 효과도 큰 것은 아님

### **1.4 추천 데이터의 편향**

기존 추천 모델을 통해 수집한 로그를 사용하면 추천 모델 자체의 편향이 데이터에 반영될 수 있음

- 기존 모델이 구매 가능성이 높은 상품을 집중적으로 추천함
- 특정 상품의 추천 및 구매 데이터가 많이 수집됨
- 추천 여부에 따른 실제 구매 확률을 정확하게 비교하기 어려움

**경향 점수(Propensity Score)**

> 특정 사용자에게 특정 상품이 추천될 확률
> 
- 인과 추론에서 활용되는 개념
- 추천이 이루어질 확률을 이용하여 데이터의 편향을 보정함
- 기존 추천 정책에 의해 발생한 편향을 완화하여 추천 효과를 추정함

### **1.5 업리프트 모델의 학습 데이터 구성**

TU, FU, TD, FD는 실제 서비스에서 직접 관측할 수 없음

동일한 사용자와 상품에 대해 같은 시점에 추천한 경우와 추천하지 않은 경우를 동시에 관측할 수 없기 때문임

따라서 실제로 관측 가능한 추천 여부와 구매 여부를 기준으로 데이터를 분류함

| 클래스 | 추천 여부 | 구매 여부 | 가능한 유형 |
| --- | --- | --- | --- |
| R-P | O | O | TU, FU |
| R-NP | O | X | TD, FD |
| NR-P | X | O | FU, TD |
| NR-NP | X | X | TU, FD |
- R → Recommend
- NR → Not Recommend
- P → Purchase
- NP → Not Purchase

### **1.6 학습 라벨 설정**

기존 구매 확률 예측 모델과 업리프트 모델은 최적화하려는 목적이 다르므로 학습 라벨을 다르게 설정함

| 클래스 | 기존 구매 예측 모델 | 업리프트 모델 |
| --- | --- | --- |
| R-P | + | + |
| R-NP | − | − |
| NR-P | + | − |
| NR-NP | − | + |

**기존 구매 예측 모델**

- 구매가 발생한 데이터를 긍정 라벨로 설정함
- 구매 가능성이 높은 사용자와 상품을 예측하는 것이 목적

**업리프트 모델**

- TU가 포함될 수 있는 R-P, NR-NP를 긍정 라벨로 설정함
- 추천으로 인해 구매가 발생할 가능성을 파악하는 것이 목적
- 단, 긍정 라벨에 해당한다고 해서 모든 데이터가 TU인 것은 아님

**데이터 불균형 문제**

- 일반적으로 추천하지 않았고 구매도 발생하지 않은 NR-NP 데이터가 매우 많음
- 특정 클래스의 데이터가 지나치게 많으면 학습에 어려움이 발생할 수 있음
- NR-NP 데이터의 샘플링 확률을 낮추는 방법을 고려할 수 있음

⇒ 서비스의 목적에 따라 모델의 학습 방식과 평가 기준을 다르게 설정해야 함

# **2. 도메인에 따른 특징과 과제**

추천 시스템은 서비스에서 다루는 아이템의 특성, 사용자의 소비 방식, 서비스의 목적에 따라 서로 다른 특징과 과제를 가짐

따라서 모든 도메인에 동일한 추천 방식을 적용하는 것이 아니라 각 도메인의 특성을 고려하여 추천 시스템을 설계해야 함

## **2.1 음악 추천**

음악 스트리밍 서비스에서는 수많은 음악 중 사용자의 취향과 현재 상황에 적합한 음악을 추천함.

대표적인 서비스 → 스포티파이, 유튜브 뮤직, 애플 뮤직

### **1️⃣ 끝없는 재생(Endless Play)**

> 사용자가 명시적으로 재생을 중단할 때까지 음악을 연속적으로 추천하고 재생하는 특징
> 
- 사용자는 음악을 듣기 전에 몇 곡을 들을지 정해두는 경우가 적음
- 하나의 음악이 끝나면 다음 음악을 재생해야 함
- 개별 음악의 추천 정확도뿐만 아니라 음악 간의 연결성과 재생 흐름도 중요함

ex) 잔잔한 발라드를 듣고 있는 사용자에게 갑자기 강렬한 헤비메탈 음악을 추천하면 사용자 경험이 저하될 수 있음

### **2️⃣ 카탈로그 문제(Catalog Problem)**

> 추천 대상이 되는 아이템의 수가 매우 많고, 관련 데이터를 관리하기 어려운 문제
> 
- 과거 클래식 음악부터 최신 음악까지 수많은 음악이 추천 대상에 포함됨
- 새로운 음악이 지속적으로 추가됨
- 특정 장르에서는 최신 음악을 빠르게 반영하는 것이 중요함
- 외부에서 제공받은 음악의 메타데이터에 오류나 누락이 존재할 수 있음
- 추천 품질 향상을 위해 데이터 정형화 및 전처리가 중요함

### **3️⃣ 사용자 선호도 반영**

사용자의 음악 선호도를 파악하기 위해 명시적 피드백과 암묵적 피드백을 활용함

| 구분 | 설명 | 예시 |
| --- | --- | --- |
| 명시적 피드백 | 사용자가 직접 표현한 선호도 | 좋아요, 싫어요, 선호 장르 선택 |
| 암묵적 피드백 | 사용자 행동을 통해 추론한 선호도 | 건너뛰기, 재생 시간, 반복 재생 |
- 사용자의 음악 취향은 시간이 지남에 따라 변화함
- 과거의 선호도가 현재의 선호도를 항상 대변하지는 않음
- 사용자 선호도의 변화를 빠르고 정확하게 파악하는 것이 중요함

ex) 과거에는 발라드를 주로 들었지만 최근에는 힙합을 주로 듣는 사용자에게 변화된 취향을 반영하여 추천함

### **4️⃣ 반복되는 소비**

> 사용자가 이미 소비한 아이템을 반복적으로 소비하는 특징
> 
- 음악은 한 번 감상한 후에도 반복해서 감상하는 경우가 많음
- 이미 소비한 아이템이라고 해서 추천 대상에서 제외하면 안 됨
- 어떤 음악을 언제 다시 듣고 싶어 하는지 예측하기 어려움
- 기존에 좋아하는 음악과 새로운 음악 사이의 균형이 필요함

ex) 영화는 한 번 시청하면 다시 보지 않는 경우가 많지만, 음악은 하루에도 같은 곡을 여러 번 재생할 수 있음

### **5️⃣ 니치한 음악에 대한 수요**

> 대중적인 인기는 낮지만 특정 사용자층이 선호하는 음악에 대한 수요
> 

![image.png](7%EC%A3%BC%EC%B0%A8%20%C2%B7%20%EA%B9%80%EB%AF%BC%EC%84%9C/image%202.png)

음악 추천에서의 롱테일 개념도

- 음악은 다른 추천 도메인에 비해 개인의 세부적인 취향이 다양하게 나타날 수 있음
- 인기곡만 추천하면 사용자의 세부적인 취향을 충족하기 어려움
- 인기도가 낮더라도 사용자의 취향에 적합한 음악을 추천할 필요가 있음
- 추천의 다양성, 신규성, 카탈로그 커버리지와 연결되는 내용

### **6️⃣ 콘텍스트 의존성(Context Dependency)**

> 사용자의 현재 상황이나 환경에 따라 선호하는 아이템이 달라지는 특징
> 

| 콘텍스트 | 추천 음악 예시 |
| --- | --- |
| 운동 중 | 빠르고 신나는 음악 |
| 공부 중 | 집중하기 좋은 음악 |
| 잠들기 전 | 잔잔하고 편안한 음악 |
| 친구들과 함께 있을 때 | 함께 즐길 수 있는 음악 |
| 비가 오는 날 | 감성적인 음악 |

같은 사용자라도 기분, 날짜, 시간, 주변 환경에 따라 듣고 싶은 음악이 달라질 수 있음

⇒ 사용자의 평소 취향뿐만 아니라 현재 상황을 함께 고려하는 콘텍스트 기반 추천이 중요함

### **7️⃣ 사회적 영향**

사용자의 음악 소비는 개인적인 취향뿐만 아니라 사회적 환경의 영향도 받음

- 친구나 주변 사람들의 음악 취향
- SNS에서 유행하는 음악
- 좋아하는 아티스트나 인플루언서
- 다른 사람에게 자신을 어떻게 표현하고 싶은지에 대한 욕구

ex) 사용자가 평소 듣는 음악과 SNS에 공유하는 음악의 성향이 다를 수 있음

## 중요하게 본 내용

- 가장 기억에 남는 내용: 업리프트 모델링에서 사용자의 구매 확률이 높다고 해서 추천 시스템이 좋은 성능을 보인다고 판단할 수 없다는 점
- 중요하다고 생각한 이유: 추천하지 않아도 구매할 상품을 계속 추천한다면 높은 구매 전환율을 달성하더라도 실제 추천 시스템을 도입한 효과는 크지 않을 수 있기 떄문
- 다른 주제와 연결되는 부분: 업리프트 모델링은 이전에 학습한 추천 시스템의 평가지표, A/B 테스트와 연결됨

## 질문 및 토론거리

- 이해가 어려웠던 부분
    - 동일한 사용자에게 추천한 경우와 추천하지 않은 경우를 동시에 관측할 수 없는데, 실제 서비스에서는 어떻게 추천의 인과적 효과를 정확하게 추정할 수 있는지 궁금했음
    - NR-NP 데이터를 긍정 라벨로 설정하면 추천 여부와 관계없이 구매하지 않는 FD 유형도 포함되는데, 모델이 이를 어떻게 구분하여 학습하는지 궁금했음
    - 경향 점수를 활용하여 기존 추천 모델에 의해 발생한 데이터 편향을 구체적으로 어떻게 보정하는지 궁금했음
- 팀원들과 함께 이야기할 질문
    - 구매 확률이 높은 상품을 추천하는 모델과 추천으로 인한 추가 구매 효과가 높은 상품을 추천하는 모델 중 실제 서비스에서는 어떤 모델이 더 적합할까?
        - 이동민: 추천으로 인한 구매 효과가 높은 상품을 더 추천하는 것이 추천 시스템의 의의라고 생각핬다.
        - 노시은: 비교적 확실한 편인 구매 확률이 높은 상품을 추천하는게 더 좋을 것 같다.
        - 이윤성: 실질적인 구매 확률이 높은 상품을 추천하는 모델이 개인 사용자에게 더 적합한 추천 결과를 제공할 것이다.
        - 안현지: 판매가 목적인 서비스에서 추가 구매 효과를 내는 상품을 추천하는 것이 더 좋을 것 같다.
    - 음악 추천 시스템에서는 사용자가 이미 좋아하는 음악을 반복해서 추천하는 것과 새로운 음악을 발견하도록 추천하는 것 중 어느 것을 우선해야 할까?
        - 이동민: 추천에 있어서는 사용자에게 익숙한 음악을 하는 것이 좋고 새로운 음악에는 새로운 장르에 대해 따로 사용자 입력으로 추천받는 행위가 일어났을 때 추천하는 것이 좋을 것 같다.
        - 노시은: 보통 음악을 들으려고 할 때는 듣고 싶은 노래가 있을 때이기 때문에 이미 좋아하는 음악을 추천하는 게 더 좋을 것 같다.
        - 이윤성: 이미 좋아하는 음악은 플레이리스트에 있거나 자주 알고리즘에 뜰 것이므로, 새로운 음악을 발견하도록 추천하는 것이 합리적 추천 범위를 넓히게 하는 좋은 방안이 될 것이다.
        - 안현지: 음악같은 취향이 사용자마다 확고한 영역의 경우에는 사용자가 이미 좋아하는 음악을 추천하는 것이 만족도가 클 것 같다.

## 스터디 후 보완

- 새롭게 이해한 내용
    - 구매 확률이 높은 상품을 추천하는 것과 추천으로 인해 추가적인 구매를 발생시키는 것은 서로 다른 목적이며, 서비스의 목표에 따라 적합한 추천 방식을 선택해야 함
    - 업리프트 모델은 사용자의 구매 유형을 직접 구분하는 것이 아니라 추천 여부와 구매 여부에 따른 데이터를 활용하여 추천의 효과를 추정한다는 점을 이해함
    - 팀원들과의 토론을 통해 음악 추천에서는 새로운 음악을 발견하는 것뿐만 아니라 사용자가 이미 좋아하는 음악을 반복해서 추천하는 것도 사용자 만족도를 높이는 데 중요하다는 점을 이해함
    - 추천 시스템은 모델의 정확도뿐만 아니라 사용자의 소비 목적, 아이템의 특성, 서비스의 운영 목적을 종합적으로 고려해야 함
- 수정하거나 추가할 내용
    - A/B 테스트를 통해 추천 집단과 비추천 집단의 구매율을 비교하여 추천의 인과적 효과를 추정하는 방법을 추가적으로 학습할 필요가 있음
    - 경향 점수를 활용한 데이터 편향 보정 방법과 NR-NP 데이터의 샘플링이 모델 학습에 미치는 영향을 구체적으로 알아볼 필요가 있음
    - 음악 추천에서 기존에 좋아하는 음악을 추천하는 활용(Exploitation)과 새로운 음악을 발견하도록 하는 탐색(Exploration) 사이의 균형을 어떻게 설정하는지 추가적으로 알아보고자 함
    - 도메인별 특성에 따라 추천 방식뿐만 아니라 평가 지표도 어떻게 다르게 설정해야 하는지 이전에 학습한 평가 지표와 연결하여 정리할 필요가 있음
