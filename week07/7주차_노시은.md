# **내가 맡은 범위**

- **담당 절·주제:** 8.5.5 음식 추천 ~ 8.6 정리
- **이 범위를 맡은 이유 또는 연결되는 내용:** 추천 시스템이 실제 서비스에 적용될 때 분야에 따라 어떤 특징과 과제가 나타나는지 이해하는 장이다. 음식 추천과 직업 추천의 사례를 살펴보며 사용자의 기호뿐만 아니라 건강, 상황, 공평성 등 다양한 요소를 고려하여 추천 시스템을 설계하는 방법을 알아볼 수 있다.

# **배운 내용 정리**

### **1. 음식 추천 (8.5.5)**

- **개념:** 사용자의 기호, 건강 상태, 생활 환경 등을 고려해서 적절한 음식이나 조리 레시피를 추천하는 방법
- **특징**
    - 영화나 음악 추천과 달리 사용자의 건강에 직접적인 영향을 미침
    - 적절한 식사 선택을 통해 비만이나 당뇨병 등 음식과 관련된 질병의 예방에 도움을 줄 수 있음
    - 사용자의 기호뿐만 아니라 건강과 실제 식사가 가능한 환경을 고려해야 함
- **주요 고려 사항:** 생활 환경의 영향, 사전 준비, 이미지 활용의 어려움

#### **1-1. 생활 환경의 영향**

- **개념:** 사용자의 생활 환경이 음식 선택에 영향을 미치는 것
- **특징**
    - 요일, 날짜, 시간, 장소 등 상황에 따라 사용자가 선택하는 음식이 달라질 수 있음
    - 문화적 배경이나 생활 방식에 따라 음식에 대한 선호도가 달라질 수 있음
    - 개인의 가치관이나 상황에 따라 소비할 수 있는 음식이 제한됨

⇒ 음식 추천에서는 단순히 사용자가 좋아하는 음식을 추천하는 것이 아니라 사용자의 생활 환경과 상황을 함께 고려해야 함

#### **1-2. 사전 준비**

- **개념:** 추천된 음식을 실제로 조리하거나 소비하기 위해 필요한 조건을 고려하는 것
- **특징**
    - 음식 추천에는 이미 만들어진 식품을 추천하는 방법과 조리 레시피를 추천하는 방법이 있음
    - 레시피를 추천하더라도 필요한 조건이 갖추어지지 않으면 실제로 음식을 조리할 수 없음

⇒ 사용자의 기호에 맞는 음식이라도 실제로 조리할 수 없는 경우에는 적절한 추천이라고 보기 어려움

#### **1-3. 이미지 활용의 어려움**

- **개념:** 음식 이미지에서 추천에 필요한 메타 데이터를 추출하는 과정에서 발생하는 어려움
- **특징**
    - 음식 추천에서는 칼로리, 식재료, 장르 등의 메타 데이터가 중요함
    - SNS에서 공유되는 음식에는 이러한 메타 데이터가 부족할 수 있음
    - 음식 이미지를 분석하여 부족한 메타 데이터를 보완할 수 있음
- **이미지 분석이 어려운 이유**
    - 식재료를 조리하는 과정에서 형태가 달라짐
    - 불의 세기나 조미료 등에 따라 음식의 색상이 복잡하게 변화함
    - 이미지에서 구조적인 패턴을 파악하기 어려움

⇒ 음식 이미지를 추천 시스템에 활용할 수 있지만 음식의 형태와 색상이 다양하게 변화하기 때문에 정확한 정보 추출에 어려움이 있음

### **2. 직업 추천 (8.5.6)**

- **개념:** 구직자에게 적합한 직업을 추천하거나 기업에 적합한 구직자를 추천하여 서로 연결하는 방법
- **특징**
    - 구직자가 자신에게 적합한 직업을 찾도록 도움
    - 기업이 원하는 조건에 적합한 구직자를 찾도록 도움
    - 구직자와 직업을 적절하게 매칭하는 것이 구인 서비스 운영에 중요한 요소임
- **주요 고려 사항:** 상호 추천 시스템, 공평성, 사용자의 기호 데이터 취득

#### **2-1. 상호 추천 시스템**

- **개념:** 추천을 받는 사용자와 추천되는 사용자 양쪽의 기호가 일치해야 추천이 성공하는 시스템
- **특징**
    - 구직자와 기업 양쪽의 요구 사항을 모두 고려해야 함
    - 한쪽의 기호만 충족한다고 해서 추천이 성공하는 것은 아님
- **예시**
    - 구직자가 특정 기업에 취업하고 싶어도 기업이 원하는 조건에 맞지 않으면 채용되기 어려움
    - 기업이 특정 구직자를 채용하고 싶어도 구직자가 원하는 업계나 조건에 맞지 않으면 채용으로 이어지기 어려움

⇒ 직업 추천에서는 구직자와 기업 양쪽의 기호와 조건을 고려하여 추천 시스템을 설계해야 함

#### **2-2. 공평성**

- **개념:** 추천 시스템이 특정 사용자나 집단에 치우치지 않고 공평하게 추천하도록 하는 것
- **특징**
    - 직업 추천에서 공평성은 가장 중요한 고려 사항 중 하나임
    - 구직자의 성별, 나이, 학력 등의 정보만으로 채용 여부가 결정되어서는 안 됨
    - 추천 모델을 구현할 때 민감한 정보를 입력 데이터에서 제거하는 방법을 사용할 수 있음
- **발생할 수 있는 문제**
    - 민감한 정보를 직접 입력하지 않아도 다른 데이터를 조합하여 간접적으로 민감한 정보를 표현할 수 있음
    - 민감한 정보를 제거하더라도 공평성이 결여된 추천 결과가 나타날 수 있음

⇒ 단순히 민감한 정보를 제거하는 것만으로는 공평성을 보장할 수 없으므로 추천 결과를 지속적으로 확인해야 함

#### **2-3. 사용자의 기호 데이터 취득**

- **개념:** 사용자의 행동과 추천 결과를 바탕으로 사용자의 기호 정보를 수집하는 과정
- **특징**
    - 직업 추천의 성공 여부는 실제 취업이나 이직 여부를 통해 판단할 수 있음
    - 직업을 추천한 시점부터 실제 취업까지 수개월이 걸릴 수 있음
    - 한 명의 사용자가 서비스를 통해 이직하는 횟수에는 한계가 있음
    - 사용자가 취업이나 이직에 성공하면 시스템에서 이탈할 수 있음

**기호 데이터 취득이 어려운 이유**

- 최종적인 추천 결과를 확인하기까지 많은 시간이 필요함
- 사용자 한 명으로부터 얻을 수 있는 피드백의 양이 적음
- 적은 양의 피드백만으로는 추천 시스템을 개선하기 어려움

**대체할 수 있는 사용자 행동- 이직 그 전 단계의 행동**

- 구인 공고에 지원했는가
- 지원에 대해 기업이 답변했는가
- 면접을 진행했는가

이러한 중간 단계의 행동을 바탕으로 추천의 성공 여부를 정의하고 사용자의 기호 정보를 얻을 수 있음

⇒ 기호 데이터의 질과 양은 트레이드오프 관계에 있으므로 서비스의 특성에 맞게 적절한 데이터를 활용해야 함

### **3. 정리 (8.6)**

- **주요 내용**
- 다양한 서비스의 추천 시스템 특성을 파악하고 실제로 사용해 보는 것이 추천 시스템 관련 기술을 이해하는 데 도움이 됨

# **중요하게 본 내용**

- **가장 기억에 남는 내용:** 직업 추천 시스템에서 성별이나 나이와 같은 민감한 정보를 입력 데이터에서 제거하더라도 다른 데이터를 조합하는 과정에서 편향된 추천 결과가 나타날 수 있다는 점이다.
- **중요하다고 생각한 이유:** 민감한 정보를 제거하면 공평한 추천이 가능하다고 생각했지만, 실제로는 다른 정보가 간접적으로 영향을 미칠 수 있다는 것을 알게 되었다. 따라서 추천 시스템을 설계할 때 정확도뿐만 아니라 공평성도 고려하고 추천 결과를 지속적으로 확인해야 한다고 생각했다.
- **다른 주제와 연결되는 부분:** 앞에서 배운 추천 시스템 평가에서는 추천 정확도와 사용자 만족도 등을 평가했다면, 이번에는 음식 추천과 직업 추천처럼 서비스의 특성에 따라 건강이나 공평성 등 추가적인 평가 기준이 필요하다는 점을 확인할 수 있다. 또한 직업 추천은 구직자와 기업 양쪽의 기호를 고려한다는 점에서 앞에서 배운 상호 추천 시스템과 연결된다.

# **질문 및 토론거리**

- **이해가 어려웠던 부분:** 직업 추천 시스템에서 민감한 정보를 직접 사용하지 않더라도 다른 데이터를 조합하여 편향된 결과가 나타날 수 있다는 부분이 잘 와닿지 않는다. 실제로 어떤 데이터가 간접적으로 편향을 발생시키는지, 추천 결과의 공평성을 어떤 지표와 방법으로 평가할 수 있는지 더 알아보고 싶다.
- **팀원들과 함께 이야기할 질문:** 직업 추천 시스템에서 실제 취업이나 이직 여부를 기준으로 평가하면 정확한 결과를 얻을 수 있지만 데이터 수집에 오랜 시간이 걸린다. 반면 지원이나 면접 여부를 기준으로 평가하면 빠르게 데이터를 수집할 수 있지만 실제 취업으로 이어진다는 보장이 없다. 이러한 상황에서 어떤 데이터를 기준으로 추천 시스템을 개선하는 것이 효과적일까?
    - **이윤성**: 지원이나 면접 여부 데이터를 바탕으로 하여 그 외 데이터 중 실제 취업과 관련된 데이터를 추가 수집하여 적용하는 것이 효과적일 것이다.
    - **이동민**: 기업에 채용후기, 구직자에게 취업후기를 남기는 공간을 만들어서 데이터를 확보하는 것도 좋을 것 같다.
    - **김민서**: 빠르게 수집할 수 있는 데이터는 주기적으로 반영을 하고 수집이 오래 걸리는 경우는 후에 반영을 해서 보완을 한다
    - **안현지**: 빠르게 모을 수 있는 지원이나 면접여부를 기준으로 자주 개선하고 실제 취업 데이터로 방향이 맞는지 주기적으로 검증하는 방식이 효과적일 것 같다.

## 스터디 후 보완

- 새롭게 이해한 내용: 추천 시스템은 단순히 구매 확률을 높이는 것보다 추천을 통해 추가적으로 발생하는 효과가 중요하다는 것을 알게 되었다.
- 수정하거나 추가할 내용: 서비스 도메인에 따라 추천 목적과 사용자 행동이 다르므로 이에 적합한 평가 기준을 설정할 필요가 있다.
