## 내용 1 - 배치 추천과 실시간 추천

- **추천 시스템의 기본 흐름**
    - 모델 학습 → 특징량 추출 및 업데이트 → 예측 → 추천 결과 제공
    - 데이터 갱신 주기와 처리 시점에 따라 배치 추천과 실시간 추천으로 구분
- **배치 추천(Batch Recommendation)**
    - 정해진 시각에 데이터를 일괄 처리하여 추천 결과 생성
    - 대량 데이터 처리에 효율적이지만 최신 사용자 행동 반영에 한계
    - **Example**
        - 매일 자정 사용자별 추천 영화 목록 생성
        - 인기 영화 순위 집계 및 정기 추천 메일 발송
- **실시간 추천(Real-time Recommendation)**
    - 사용자 행동이나 요청에 따라 특징량 및 추천 결과를 빠르게 갱신
    - 최신 취향 반영에 유리하지만 서버 부하와 구현 복잡도 증가
    - **Example**
        - 사용자가 특정 영화를 시청한 직후 유사 영화 추천
        - 음악을 건너뛰는 행동을 반영하여 다음 추천 변경
- **선택 기준**
    - 데이터 업데이트 빈도, 응답 속도, 서버 운영 비용
    - 서비스 특성에 따라 배치와 실시간 추천의 혼합 가능

## 내용 2 - 개요 추천과 연관 아이템 추천

- **개요 추천(Overview Recommendation)**
    - 신규순 또는 인기순으로 아이템을 정렬하여 추천하는 방식
    - 개인 취향 정보가 없어도 구현 가능하여 콜드 스타트 대응에 유용
- **신규순 및 인기순 추천**
    - 신규순: 등록일 또는 출시일을 기준으로 정렬
    - 인기순: 조회수, 클릭 수, 시청 수 등을 집계하여 정렬
    - **Example**
        - 최신 등록 영화 10개 추천
        - 최근 일주일간 가장 많이 시청한 영화 추천
- **연관 아이템 추천(Related Item Recommendation)**
    - 장르, 태그, 콘텐츠 특징량 등을 활용하여 유사 아이템 추천
    - 유사도 계산 결과를 사전에 DB에 저장하여 빠르게 조회 가능
    - **Example**
        - SF 영화를 선택하면 장르와 줄거리가 유사한 영화 추천
- **추천 API 활용**
    - 웹 서비스와 DB 사이에서 추천 로직을 별도로 관리
    - 추천 결과 필터링, 알고리즘 변경 및 A/B 테스트 지원

## 내용 3 - 개인화 추천과 벡터 기반 추천

- **개인화 추천(Personalized Recommendation)**
    - 사용자 프로필, 클릭 기록, 시청 기록 등을 활용한 맞춤형 추천
    - 사용자별 추천 목록을 미리 계산하는 배치 방식과 요청 시 계산하는 실시간 방식으로 구성 가능
- **벡터 기반 개인화(Vector-based Personalization)**
    - 사용자와 아이템의 특징을 수치 벡터로 표현
    - 코사인 유사도 등을 활용하여 사용자 취향과 가까운 아이템 추천
    - **Example**
        - 특징 기준: `[액션, 로맨스, 코미디]`
        - 영화 A: `[0.9, 0.1, 0.2]`
        - 영화 B: `[0.7, 0.3, 0.4]`
        - 사용자 벡터: `[0.8, 0.2, 0.3]`
        - 유사도가 높은 영화부터 추천
- **실시간 개인화**
    - 사용자의 최신 행동을 반영하여 사용자 벡터 갱신
    - 추천 API에서 아이템 벡터와 유사도를 계산하여 결과 반환

## 중요하게 본 내용

- **가장 기억에 남는 내용:**
    - 추천 알고리즘뿐 아니라 DB, API, 데이터 처리 시점까지 고려해야 실제 추천 시스템 구현이 가능하다는 점
- **중요하다고 생각한 이유:**
    - 추천 정확도뿐 아니라 응답 속도, 데이터 최신성, 서버 비용이 사용자 경험에 직접적인 영향을 미치기 때문
- **다른 주제와 연결되는 부분:**
    - 콘텐츠 기반 필터링과 벡터 유사도 계산의 연결
    - 개인별 선호도를 계산한 뒤 그룹의 취향을 통합하는 그룹 영화 추천 시스템으로 확장 가능

## 질문 및 토론거리

- **이해가 어려웠던 부분:**
    - 배치와 실시간 처리를 혼합할 때 각 처리 단계의 갱신 주기를 결정하는 기준
    - 사용자 행동 데이터가 부족한 경우 사용자 벡터를 생성하는 방법
- **팀원들과 함께 이야기할 질문:**
    - 영화 추천 서비스에 배치 추천과 실시간 추천 중 어떤 방식이 더 적합한가?
    **김민서**: 배치 추천이 적합하다고 생각한다. 영화는 음악처럼 연속해서 보지 않기 때문에 실시간 추천보다는 배치 추천이 적합하다고 생각한다.
        
        **노시은**: 영화는 한 번 보고나서 다음 영화를 고르는 데에 시간이 걸려서 실시간 추천의 장점이 큰 의미가 없을 것 같다. 배치 추천이 더 적합할 것 같다. 
        **안현지**:  데이터가 많아서 무거울거 같아서 주기적으로 추천하는 배치 추천이 좋을 것 같다. 
        **이동민**: 배치추천. 영화는 상영하는 주기가 n개월 단위이고, 넷플릭스같은 ott사이트에서도 긴 기간 올라와있기 때문에 실시간 추천보다는 배치추천이 어울린다.
        
    - 개인별 추천 점수를 그룹 추천으로 통합할 때 어떤 계산 방식이 효과적인가?
    **김민서**: 개인의 추천점수를 가중치로 곱해서 계산하면 좋을 것 같다.
    **노시은**: 개인의 점수를 합칠 때, 가중평균을 적용하여 통합하는 것이 좋을 것 같다.
    **안현지**:  영화추천이라는 기준으로 치면 한명이라도 지루하면 안되니까 평점을 평균 내는 방식이 모두가 소외되지않는 추천을 해줄 것 같아서 좋을 것 같다.
    **이동민**:  최대한 모두에게 보편적인 방향으로 편향되게 계산하되, 상한과 하한을 정해두는 것도 좋을 것 같다.
