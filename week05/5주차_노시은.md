## 내가 맡은 범위

- 담당 절·주제: 6장 추천 시스템의 구축과 운영 – 6.3 실제 시스템 예 ~ 6.4 정리
- 이 범위를 맡은 이유 또는 연결되는 내용: 앞에서 배운 추천 시스템의 설계와 알고리즘이 실제 서비스에서 어떻게 활용되는지 이해하는 장이다. 뉴스 추천 서비스를 예시로 배치 추천과 실시간 추천의 구조를 비교하며 추천 시스템의 운영 과정을 살펴볼 수 있다.

## 배운 내용 정리

> **6.3~6.4 요약**
> 
> 
> 실제 뉴스 추천 시스템을 예시로 배치 추천과 실시간 추천의 처리 과정을 설명
> 
> - **배치 추천:** 사용자의 과거 행동 데이터를 바탕으로 추천 결과를 미리 계산하고 정해진 시점에 제공
> - **실시간 추천:** 사용자의 최신 행동을 반영하여 추천 결과를 빠르게 갱신
> - **스코어링과 재순위:** 추천 후보의 점수를 계산하고 적절한 순서로 정렬
> - **특징량 업데이트:** 사용자의 새로운 행동을 반영하여 추천에 사용하는 정보를 갱신
> 
> 실제 추천 시스템에서는 추천 정확도뿐만 아니라 계산 속도와 데이터 갱신 방법도 중요함
> 

### 1. 실제 시스템 예 (6.3)

- **개념:** 추천 알고리즘을 실제 서비스에 적용할 때 사용하는 시스템 구조와 처리 과정을 설명
- **대표 예시:** 뉴스 추천 서비스
    - 사용자가 과거에 읽었던 기사와 클릭 기록을 바탕으로 관심 있을 만한 뉴스를 추천
    - 추천 결과를 미리 계산
- **특징**
    - 데이터 수집, 저장, 모델 학습, 스코어링, 결과 제공 과정이 필요
    - 서비스의 목적에 따라 배치 추천과 실시간 추천을 구분하여 사용
    - 추천 결과의 정확도와 함께 응답 속도, 계산 비용도 고려해야 함

### 2. 배치 추천 (6.3.1)

- **개념:** 추천에 필요한 데이터 처리와 계산을 미리 수행한 뒤, 저장된 추천 결과를 사용자에게 제공하는 방식
- **예시:** 사용자의 관심사를 분석하여 정해진 시간에 추천 뉴스 알림을 전송하는 서비스
- **특징**
    - 추천 요청이 발생하기 전에 모델 학습과 스코어링을 수행
    - 추천 결과를 미리 준비하므로 서비스 제공 시 계산 부담 감소
    - 반면 사용자의 최신 행동이 추천 결과에 바로 반영되지X

#### 2-1. 후보 기사 선정

- **개념:** 전체 기사 중에서 사용자에게 추천할 가능성이 있는 기사를 추리는 과정
- **필요한 이유:** 모든 기사에 대해 추천 점수를 계산하면 많은 시간과 자원이 필요하기 때문
- **고려해야할 정보**
    - 최근 등록된 기사인지
    - 사용자가 이미 읽거나 클릭한 기사인지
    - 사용자에게 이미 전송한 기사인지
    - 추천 대상으로 적절한 기사인지

⇒ 추천할 필요가 없는 기사를 미리 제외하여 계산량을 줄일 수 있음

#### 2-2. 모델링

- **개념:** 사용자의 과거 행동 데이터를 바탕으로 어떤 기사에 관심을 가질지 예측하는 모델을 학습하는 과정
- **특징**
    - 모델 학습은 일정한 주기로 수행
    - 새로운 요청이 발생할 때마다 모델 전체를 다시 학습할 필요X
    - 학습한 모델은 이후 추천 후보의 점수를 계산하는 데 사용

#### 2-3. 스코어링

- **개념:** 학습한 모델을 활용하여 사용자와 기사 사이의 적합도를 점수로 계산하는 과정
- **특징**
    - 사용자 특징량과 기사 특징량을 모델에 입력
    - 계산된 점수를 바탕으로 추천 우선순위를 결정
    - 결과를 데이터베이스에 저장하여 나중에 활용

#### 2-4. 푸시 전송

- **개념:** 추천 점수가 높은 기사를 선정하여 사용자에게 알림으로 제공하는 과정
- **장점:** 미리 계산된 결과를 활용하므로 정해진 시간에 많은 사용자에게 추천을 제공하기 쉬움
- **한계:** 추천 결과를 계산한 이후 사용자의 관심사가 바뀌면 즉시 반영하기 어려움

### 3. 실시간 추천 (6.3.2)

- **개념:** 사용자가 서비스를 이용하면서 발생시키는 새로운 행동을 반영해 추천 결과를 제공하는 방식
- **대표 예시:** 사용자가 특정 뉴스를 클릭한 직후 관련 기사를 추천하는 서비스
- **특징**
    - 사용자의 최신 관심사를 추천에 반영
    - 행동 로그와 사용자 특징량을 빠르게 갱신해야 함
    - 사용자가 기다리지 않도록 짧은 시간 안에 계산을 완료해야 함
    - 배치 추천보다 응답 속도와 시스템 처리 성능이 중요

#### 3-1. 행동 로그 수집

- **개념:** 사용자가 서비스에서 수행한 행동을 기록하는 과정
- 특징
    - 사용자의 현재 관심사를 파악하는 데 사용
    - 새로운 행동 정보가 쌓이면 추천에 사용하는 사용자 특징량을 업데이트

#### 3-2. 스코어링과 재순위

- **스코어링:** 데이터베이스에서 정보를 읽은 후 추천 후보 기사에 대해 사용자의 관심 가능성을 점수로 산출
- **재순위:** 계산된 점수와 추가 조건(피드백,최신성 등)을 고려해 추천 순서를 재나열하는 과정
- **특징**
    - 병렬로 계산하면 여러 후보의 점수를 동시에 계산하여 응답 시간을 줄일 수 있음
    - 캐시를 도입하면 데이터 접근 시간을 줄일 수 있음
    - 재순위 과정에서는 추가적으로 사용자의 피드백과 추가 조건을 반영

⇒ 실시간 추천에서는 알고리즘의 정확도뿐만 아니라 제한된 시간 안에 추천 결과를 제공하는 것이 중요

#### 3-3. 특징량 업데이트

- **개념:** 사용자의 새로운 행동을 반영하여 추천 모델에 입력하는 사용자 특징량을 갱신하는 과정
- **처리 과정**
    1. 사용자가 새로운 기사를 클릭
    2. 과거에 클릭한 기사와 새로 클릭한 기사의 정보를 확인
    3. 학습 완료 모델을 활용하여 새로운 사용자 특징량을 계산
    4. 갱신한 특징량을 이후 추천에 활용

⇒ 새로운 행동이 발생할 때마다 모델 전체를 재학습하지 않고, 학습된 모델을 이용해 사용자 특징량을 업데이트

### 4. 배치 추천과 실시간 추천 비교

| 구분 | 배치 추천 | 실시간 추천 |
| --- | --- | --- |
| 계산 시점 | 미리 계산 | 사용자 행동 또는 요청 시 |
| 데이터 | 과거 데이터 중심 | 최신 행동 반영 |
| 응답 속도 | 미리 계산해 빠르게 제공 가능 | 요청 시 빠른 계산 필요 |
| 장점 | 대량 처리에 유리 | 현재 관심사 반영 |
| 단점 | 최신 관심사 반영이 늦음 | 계산 및 운영 부담 |
| 활용 예시 | 뉴스 푸시 알림 | 기사 클릭 후 관련 뉴스 추천 |

→ 배치 추천은 미리 계산해 효율적으로 제공, 실시간 추천은 사용자의 최신 관심사를 반영

→ 실제 서비스에서는 목적에 따라 적절한 방식을 선택

### 5. 정리 (6.4)

- **주요 내용**
    - 추천 시스템의 설계 패턴을 이해함
    - 다단계 추천을 활용하여 후보 선정과 점수 계산을 나누어 처리할 수 있음
    - 근사 최근접 탐색 등을 활용하여 대규모 추천에서 계산 효율을 높일 수 있음
    - 실제 서비스에서는 배치 추천과 실시간 추천을 상황에 맞게 활용함
    - 행동 로그와 사용자 특징량을 관리하고 지속적으로 갱신해야 함

## 중요하게 본 내용

- 가장 기억에 남는 내용: 실시간 추천에서 사용자의 새로운 행동을 반영하기 위해 매번 모델 전체를 재학습하는 것이 아니라, 기존에 학습한 모델을 활용하여 사용자 특징량을 업데이트할 수 있다는 점이다.
- 중요하다고 생각한 이유: 실시간 추천은 모델을 매번 새로 학습하는 것이 아니라 최신 행동 정보를 반영해 추천 결과를 갱신한다는 점이 인상 깊었다. 또한 추천 정확도뿐만 아니라 처리 속도도 중요하다는 것을 알게 되었다.
- 다른 주제와 연결되는 부분: 앞에서 배운 추천 알고리즘을 실제 서비스에서 어떻게 활용하는지 연결된다.

## 질문 및 토론거리

- 이해가 어려웠던 부분: 실시간 추천에서 병렬 처리와 캐시를 활용해 계산 속도를 높이는 방법이 어려웠다. 특히 두 방법이 실제 추천 시스템에서 어떻게 적용되는지 더 알아보고 싶다.
- 팀원들과 함께 이야기할 질문: 배치 추천은 최신 관심사를 빠르게 반영하기 어렵고, 실시간 추천은 계산 비용이 많이 발생할 수 있는데 실제 뉴스 추천 서비스에서 두 방식의 장점을 함께 활용하려면 어떻게 시스템을 설계해야 할까?
    - **이윤성**: 초기에 배치 추천 시스템을 바탕으로 다양한 선택지를 제공함과 동시에 선택 비율 데이터를 피드백으로 적용하여 후반 추천에 실시간 추천을 바탕으로 설계하는 것이 좋을 것 같다.
    - **이동민**: 실시간 추천은 잘 보이는 곳에 노출되게 하고 배치 추천은 사용자가 더 탐색했을 때 보는 방식으로 할 수 있을 것 같다.
    - **김민서**: 배치 추천 시스템으로 먼저 후보를 선정하고 이후에 실시간 추천으로 재랭킹을 해서 추천한다.
    - **안현지**: 모델학습같이 무거운 건 배치추천으로 하고  가벼운 일들은 실시간 추천으로 하는 방식이 좋을 것 같다.

## 스터디 후 보완

- 새롭게 이해한 내용: 추천과 실시간 추천은 어느 한쪽이 무조건 좋은 방식이 아니라 서비스의 목적에 따라 선택하는 방식이라는 점이다.
- 수정하거나 추가할 내용: 병렬 처리와 캐시를 활용하면 응답 시간을 줄일 수 있지만, 캐시 정보가 오래되면 최신 사용자 행동이 제대로 반영되지 않을 수 있으므로 데이터 갱신 주기도 고려해야 한다.
