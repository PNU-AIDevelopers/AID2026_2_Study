### 내용 1 - 추천 알고리즘 비교

- **추천 알고리즘의 주요 평가 기준**
    - **예측 정확도, 계산 속도, 데이터 요구량, 콜드 스타트 대응 능력** 등
    - 서비스의 목적과 데이터 규모에 따른 적절한 알고리즘 선택의 중요성
- **주요 추천 알고리즘**
    - **무작위 추천:** 사용자 취향과 관계없이 무작위로 아이템을 추천하는 방식
    - **통계 기반 추천:** 인기순, 평균 평점순 등 통계 정보를 이용하는 방식
    - **협조 필터링:** 사용자 간 선호도나 아이템 간 관계를 활용하는 방식
    - **행렬 분해:** 사용자-아이템 평점 행렬에서 잠재 요인을 추출하여 선호도를 예측하는 방식
- **알고리즘별 특징**
    - **단순 추천**: 빠른 계산 속도와 낮은 개인화 성능
    - **개인화 추천**: 사용자 행동 데이터 활용을 통한 추천 정확도 개선 가능성
- **Example**
    - 서비스 초기: 사용자 **데이터 부족**으로 **인기순** 추천 활용
    - 서비스 성장 이후: 사용자 평점 **데이터 축적**을 통한 **협조 필터링** 및 **행렬 분해 방식** 도입

### 내용 2 - MovieLens 데이터셋

- **MovieLens 데이터의 구성**
    - 영화 정보, 사용자 평점 등을 포함한 추천 시스템 실습용 데이터셋
    - `movies.dat`: 영화 ID, 제목, 장르 정보
    - `ratings.dat`: 사용자 ID, 영화 ID, 평점, 타임스탬프
- **EDA(탐색적 데이터 분석)**
    - 추천 모델 구현 전 사용자 수, 영화 수, 평점 분포 등을 파악하는 과정
    - `groupby()`: 특정 기준에 따른 데이터 그룹화 및 통계 계산

```
# 평점별 평가 횟수
movielens.groupby('rating')['movie_id'].count()

# 영화별 평균 평점
movielens.groupby('movie_id')['rating'].mean()
```

- **학습 및 테스트 데이터 분리**
    - 사용자별 최근 평가 영화 5개를 테스트 데이터로 분리하는 방식
    - 나머지 데이터를 학습에 활용하여 예측 성능 평가

```
movielens['rank'] = movielens.groupby(
    'user_id')['timestamp'].rank(
        ascending=False, method='first'
    )

train = movielens[movielens['rank'] > 5]
test = movielens[movielens['rank'] <= 5]
```

- **추천 성능 평가 지표**
    - **RMSE:** 실제 평점과 예측 평점 사이의 오차를 측정하는 지표로, 낮을수록 우수한 성능
    - **Precision@K:** 상위 K개 추천 중 실제 선호 아이템이 차지하는 비율
    - **Recall@K:** 실제 선호 아이템 전체 중 상위 K개 추천에 포함된 비율
- **Example**
    - 실제 선호 영화 6개 중 3개가 추천 상위 5개에 포함된 상황
    - **Precision@5 = 3/5 = 0.6** (추천 정확도 60%)
    - **Recall@5 = 3/6 = 0.5** (전체 선호 영화의 50% 발견)
    - `@5`: 추천 순위 상위 5개를 평가 대상으로 지정한다는 의미

### 내용 3 - 무작위 추천

- **무작위 추천의 특징**
    - 사용자 취향과 관계없이 무작위로 평점을 예측하거나 아이템을 추천하는 방식
    - 다른 추천 알고리즘의 성능을 비교하기 위한 베이스라인
    - 구현이 간단하지만 개인별 선호도를 반영하지 못한다는 한계
- **핵심 코드**

```
import numpy as np

np.random.seed(0)

pred_matrix = np.random.uniform(
    0.5, 5.0,
    (len(unique_user_ids), len(unique_movie_ids))
)
```

- `seed(0)`: 동일한 난수 결과를 재현하기 위한 설정
- `niform(0.5, 5.0)`: 0.5 이상 5.0 미만의 무작위 실수 생성
- `pred_matrix`: 사용자별·영화별 예측 평점을 저장하는 행렬
- **Example**
    - 사용자 A에게 영화 X의 예측 평점을 4.2점, 영화 Y를 2.7점으로 무작위 부여
    - 실제 선호도와 무관한 결과이므로 개인화 추천과의 성능 비교 기준으로 활용

### 내용 4 - 통계 및 규칙 기반 추천

- **통계 기반 추천의 특징**
    - 영화별 평가 수, 평균 평점, 인기순 등의 통계 정보 활용
    - 사용자별 선호 데이터가 부족한 상황에서도 적용 가능한 방식
    - **한계** - 개인별 취향을 충분히 반영하지 못함
- **최소 평가 수의 필요성**
    - 평균 평점만 사용할 경우 평가 수가 적은 영화의 과도한 상위 노출 가능성
    - 최소 평가 수 임계값 설정을 통한 추천 결과의 신뢰성 개선
- **핵심 코드**

```
# 영화별 평가 수와 평균 평점
movie_stats = movielens.groupby('movie_id')[
    'rating'
].agg(['count', 'mean'])

# 평가 수 100개 이상인 영화만 선별
valid = movie_stats['count'] >= 100

# 평균 평점 내림차순 정렬
movie_stats[valid].sort_values(
    'mean', ascending=False
).head()
```

- `count`: 영화별 평가 수
- `mean`: 영화별 평균 평점
- `>= 100`: 평가 수가 100개 이상인 영화만 선별하는 조건
- **데모그래픽 필터링**
    - 나이, 성별, 거주지 등 사용자 속성을 기준으로 그룹을 구분하여 추천하는 방식
    - 사용자 정보의 정확성과 집단별 편향에 대한 고려 필요
- **Example**
    - **영화 A**: 평균 평점 **5.0**점, 평가 수 **1**개
    - **영화 B**: 평균 평점 **4.5**점, 평가 수 **1,000**개
    - 최소 평가 수 100개 적용 시 영화 B만 추천 후보에 포함
    - 평가 수 임계값에 따른 추천 순위 및 후보군 변화

## 중요하게 본 내용

- **가장 기억에 남는 내용**
    - 평균 평점이 높더라도 평가 수가 적으면 신뢰하기 어려우므로 최소 평가 수 설정의 중요성

    - 평가 수 임계값 설정에 따른 추천 후보 및 순위 변화 가능성

## 질문 및 토론거리

- **이해가 어려웠던 부분**
    - RMSE와 Precision@K, Recall@K의 평가 목적 차이
    - 실제 서비스에서 추천 목적에 따라 우선적으로 고려해야 할 평가 지표의 선정 기준
- **팀원들과 함께 이야기할 질문**
    - 평균 평점 5.0점에 평가 수 10개인 영화와 평균 평점 4.5점에 평가 수 1,000개인 영화 중 우선 추천 대상?
    김민서: 평가 수가 많은 영화 B를 추천하는 것이 좋을 거 같다.
    안현지:4.5점 1000개 영화를 먼저 추천하는게 좋을 거 같다.  5점 10개는 특정 팬층의 영향일수도 있으니까 4.5 1000명이 믿을만 하다.
    이동민: 가중치를 학습하거나 정해두는게 좋을 것 같다. 100개가 더 좋게 만들 수도 있고 10개라도 더 좋게 만들 수도 있지 않을까.
    - 추천 신뢰성과 후보 다양성을 모두 확보하기 위한 적절한 최소 평가 수 임계값의 설정 방법?
    김민서: 평가 수가 유의미한 값을 가지도록 설정한다.
    안현지: 여러 값으로 실험해보고 정하는게 제일 좋을 것 같다. 
    이동민: 단순한 개수 임계값만 쓰기 보다는
    리뷰 자체의 글자 수나 리뷰어가 어느정도 활동했는지 여러가지 임계값을 두는 게 좋을 것 같다.
