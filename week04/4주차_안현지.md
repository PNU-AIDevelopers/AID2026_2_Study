### 1. 연관 규칙 (5.5)

- **개념:** 대량의 구매 이력에서 "A와 B는 함께 구매되는 경우가 많다"는 규칙을 찾는 방법
- **대표 예시:** 기저귀와 맥주
    - 기저귀를 사는 남성이 맥주도 함께 사는 경향을 발견
    
    **⇒ 강점:** 사람이 예상하지 못한 의외의 조합을 발견할 수 있음 
    매장 배치 변경, 마케팅, 세트 상품 구성에 활용
    
- **특징**
    - 1994년에 대량 데이터도 빠르게 계산하는 방법이 제안되었다.
    - 계산 간단, SQL로도 구현 가능
    - 구매 이력뿐 아니라 북마크나 열람 이력 같은 행동 데이터에도 적용 가능
    - 열람 데이터에서는 일정 횟수 이상 본 것만 인정하거나 사용자 대신 세션 단위로 집계
- **예시 데이터 (표 5-3):** 사용자 4명, 아이템 3개

|  | 아이템 A | 아이템 B | 아이템 C |
| --- | --- | --- | --- |
| 사용자 1 | ○ | ○ |  |
| 사용자 2 | ○ | ○ |  |
| 사용자 3 |  |  | ○ |
| 사용자 4 | ○ | ○ | ○ |

#### 1-1. 지지도 (support)

- 어떤 아이템(또는 조합)이 전체 데이터 중 등장한 비율
    - 지지도(A) = 3/4 = 0.75
    - 지지도(B) = 3/4 = 0.75
    - 지지도(C) = 2/4 = 0.5
    - 지지도(A and B) = 3/4 = 0.75
- 자주 함께 등장하는 조합일수록 값이 높음

#### 1-2. 확신도 (confidence)

- A가 등장했을 때 B도 등장하는 비율
    - 확신도(A ⇒ B) = A와 B 동시 등장 수 / A 등장 수 = 3/3 = 1.0
- 이때 A를 **조건부(antecedents)**, B를 귀결부(consequents)

#### 1-3. 리프트값 (lift)

- A와 B의 등장이 얼마나 상관관계가 있는지 나타내는 값
    - 리프트(A ⇒ B) = 지지도(A and B) / (지지도(A) × 지지도(B)) = 0.75 / (0.75 × 0.75) ≈ 1.333
- **해석 방법**
    - 리프트 = 1: 서로 관계없음 (독립)
    - 리프트 > 1: 양의 상관관계
    - 리프트 < 1: 음의 상관관계
- 아이템이 3개 이상인 조합에도 계산 가능
- 리프트값에 로그를 취하면 점별 상호정보량**(PMI)**
- **추천에서의 의미:** 리프트가 높으면 A를 산 사람에게 B를 추천했을 때 구매 확률이 높아질 가능성 있음
    - 하지만 상관관계일 뿐 인과관계가 아니므로 실제 추천으로 검증 필요

#### 1-4. Apriori 알고리즘을 활용한 고속화

- **문제:** 아이템과 사용자 수가 늘어나면 조합의 수가 기하급수적으로 늘어나 모두 계산할 수 없음
- **해결:** Apriori 알고리즘은 **지지도가 일정 이상인 아이템과 조합만** 계산→ 속도 높임
- **임곗값(min_support)이 중요**
    - 너무 높으면 일부 인기 아이템만 추천
    - 너무 낮으면 계산이 무거워지고 노이즈가 많은 아이템이 추천
- **MovieLens 실습 (mlxtend 라이브러리 사용)**
    1. 평갓값 4 이상은 1, 4 미만과 빈칸은 0으로 바꿔 사용자 × 영화 행렬을 만들기
    2. 지지도 계산: 지지도 1위는 '양들의 침묵'(약 40%의 사용자가 4점 이상)
    3. 리프트값 계산: 반지의 제왕 1편과 2편의 조합이 리프트 약 5.46으로 가장 높음
        - 리프트는 계산식이 대칭이라 조건부와 귀결부를 바꿔도 값이 같음
        - 하지만 2편을 보는 사람에게 1편을 추천하는 건 큰 의미가 없음 → 연관 규칙은 상관관계만 보여준다는 한계
- **추천 방법**
    1. 사용자가 최근 4점 이상 준 영화 5편을 입력으로 쓴다.
    2. 그중 하나라도 조건부에 포함된 규칙을 모두 찾는다.
    3. 리프트값 순으로 정렬한다.
    4. 이미 평가한 영화를 빼고 상위 10편을 추천한다.
- **결과**
    - min_support = 0.1일 때 Precision@K = 0.011, Recall@K = 0.036으로, 무작위보다는 좋지만 인기순보다 Recall이 낮았다.
    - min_support = 0.06으로 낮추면 Precision@K = 0.015, Recall@K = 0.048로 인기순보다 좋아졌다. 대신 계산 시간이 늘어나므로 실무에서는 속도도 함께 고려해 정한다.

### 2. 사용자-사용자 메모리 기반 방법 협조 필터링 (5.6)

- **특징:** 미리 계산하지 않고 데이터를 쌓아두기만 하다가 추천하는 순간에 필요한 데이터를 모두 써서 계산함→다른 방법보다 예측 시간이 오래 걸리는 경우가 많음
- **구현 3단계**
    1. 평갓값으로 사용자 간 유사도를 계산하고 비슷한 사용자를 찾는다.
    2. 비슷한 사용자의 평갓값으로 아직 평가하지 않은 아이템의 점수를 예측한다.
    3. 예측 점수가 높은 아이템을 추천한다.
- **유사도 계산: 피어슨 상관계수**
    - 두 사용자가 **공통으로 평가한 영화만** 골라서 계산한다.
    - 각 사용자의 평균을 빼고 비교하므로 점수를 짜게 주는 사람과 후하게 주는 사람의 차이가 보정된다.
    - 책에서는 유사도가 0보다 크면 비슷한 사용자로 본다.
- **예측 평갓값 계산**
    
    $$
    \hat{r}_{ay} = \bar{r}_a + \dfrac{\sum_{x} \rho_{ax}(r_{xy} - \bar{r}_x)}{\sum_{x} |\rho_{ax}|}
    
    $$
    
    - 나의 평균 점수에, 비슷한 사용자들이 "자기 평균보다 얼마나 높게 줬는지"를 유사도로 가중 평균해서 더하는 방식
    - 비슷한 사용자가 아무도 평가하지 않은 영화는 내 평균 점수로 예측
- Surprise의 KNNWithMeans로도 구현 가능. 유사도 상위 30명을 이웃으로 쓰고, user_based를 False로 바꾸면 아이템 기반이 된다
- 예시 결과 해석
    - RMSE(점수 예측)는 무작위 추천이나 인기순 추천보다 우수하다.
    - 순위 추천 성능은 인기순이나 연관 규칙보다 많이 낮다.
    - 원인: 평가 수는 적지만 점수가 높은 아이템이 상위에 올라오기 때문이다.
    - 개선: 일정 수 이상 평가된 아이템만 남기면 나아진다.

### 3. 회귀 모델 (5.7)

- **개념:** 평갓값(0.5~5.0, 0.5 간격)을 **회귀 문제**로 보고 예측
    - 머신러닝의 다양한 방법을 그대로 시도해볼 수 있다는 장점
    - 책에서는 **랜덤 포레스트**(sklearn)를 사용
- **특징량 만들기 (쉽게 말하자면 모델에게 주는 힌트)**
    - 사용자별 평갓값의 최솟값, 최댓값, 평균
    - 영화별 평갓값의 최솟값, 최댓값, 평균
    - 영화가 특정 장르에 속하는지 여부(True/False)
    
    테스트 데이터에만 있는 사용자나 영화는 학습 데이터 전체 평균으로 채운다.
    사용자 ID와 영화 ID는 그대로 넣으면 의도하지 않은 학습이 일어나므로 삭제한다.
    
- **예측과 추천**
    - 테스트 데이터 조합과 학습 데이터의 모든 사용자 × 영화 조합에 대해 점수를 예측한다.
    - 사용자가 평가하지 않은 영화 중 예측 점수 상위 10편을 추천한다.
- **결과:** RMSE = 0.988, Precision@K = 0.000, Recall@K = 0.001
    - RMSE는 무작위나 인기순보다 좋지만 사용자-사용자 협조 필터링보다는 조금 낮다.
    - 순위 추천은 무작위 수준 ⇒ 5.6과 같은 원인(평가 수가 적은데 점수가 높은 아이템) ⇒ 평가 수 임곗값으로 해결

### 4. 세 방법 결과 비교 (책 예시 결과)

| 방법 | RMSE | Precision@K | Recall@K |
| --- | --- | --- | --- |
| 연관 규칙 (min_support 0.1) | – | 0.011 | 0.036 |
| 연관 규칙 (min_support 0.06) | – | 0.015 | 0.048 |
| 사용자-사용자 협조필터링(Surprise) | 0.962 | 0.002 | 0.005 |
| 회귀 모델 (랜덤 포레스트) | 0.988 | 0.000 | 0.001 |

→ 점수 예측(RMSE)은 협조 필터링이 가장 좋다. 순위 추천(Precision/Recall)은 연관 규칙이 가장 좋다. 

→ 평가 지표에 따라 좋은 알고리즘이 달라진다.

## 중요하게 본 내용

- **가장 기억에 남는 내용:** RMSE가 좋은 방법이 순위 추천에서는 오히려 무작위 수준이었다는 점. 점수를 정확히 맞히는 것과 좋은 추천 목록을 만드는 것은 다른 문제였다.
- **중요하다고 생각한 이유:** 평가 지표를 무엇으로 정하느냐에 따라 알고리즘 선택이 완전히 달라질 수 있다. 또 평가 수가 적은 아이템이 상위에 오는 문제처럼, 데이터 특성을 이해하지 못하면 복잡한 알고리즘도 성능이 나빠질 수 있다.
- **다른 주제와 연결되는 부분**
    - 5.6은 4.3에서 배운 사용자-사용자 방법을 실제 코드로 구현한 것

## 질문 및 토론거리

- **이해가 어려웠던 부분:** 회귀 모델의 RMSE는 무작위보다 좋은데 Precision@K가 0에 가까운 이유. 테스트 데이터 조합만 예측하는 것과 모든 미평가 영화의 순위를 매기는 것의 차이를 더 이해하고 싶다.
- **팀원들과 함께 이야기할 질문**
    - 반지의 제왕 1편과 2편처럼 시리즈물은 리프트가 높아도 추천 가치가 낮다. 이런 조합은 어떻게 걸러낼 수 있을까?
    **김민서**: 시리즈물은 따로 클러스팅을 해서 중복 추천을 피한다.
    **이동민**: 단순하게 시리즈인지 아닌지 속성을 추가하는 방법
    **이윤성**: 전속/후속편에 인덱스를 심어 후속편 산하에 추천되는 항목들 후보군 중 전속편인 경우, 특정 상수값을 설정하여 연관도가 낮음을 나타내는 변수를 설정하고 이를 곱하여 가치 산출 시 참고하는 값의 가치를 낮춘다. (단, 마지막 편 산하에 첫 편을 후보군으로 고려하는 경우 ‘정주행’의 가능성이 있으므로 예외의 경우로 처리하는 방법을 모색한다.)

## 스터디 후 보완

- 새롭게 이해한 내용: 추천 목록은 연관 규칙이 제일 좋았지만 점수 예측은 할 수 없다. 다른 방법도 임곗값으로 개선될 여지가 있기때문에 어떤 알고리즘이 무조건 좋다기보다는 서비스 목적과 평가 기준에 맞게 골라야된다.
- 수정하거나 추가할 내용: 연관 규칙은 점수를 예측하지 않으므로 RMSE로 평가하지 않는다. 연관 규칙 추천 방법을 더 정확히 쓰면, 리프트 순으로 정렬한 뒤 귀결부 영화의 등장 빈도가 많은 순서로 추천한다.
