## 배운 내용 정리

## 1. 적합 아이템 발견

> 사용자가 자신의 목적을 달성하는 데 적합한 아이템을 서비스 안에서 최소 1개 이상 발견하도록 하는 것
> 

예를 들어 사용자가 서울역 근처에서 식사할 식당을 찾는 상황을 생각할 수 있음

- 사용자는 서울역 근처의 모든 식당을 확인하고 싶은 것이 아님
- 자신의 취향이나 조건에 맞는 식당 몇 개만 발견해도 목적을 달성할 수 있음
- 즉, 사용자의 목적을 만족시킬 수 있는 **적합한 아이템을 최소 하나 이상 빠르게 찾도록 하는 것**이 중요함

### 적합 아이템 발견의 목표

- 사용자의 목적에 맞는 아이템을 빠르게 찾을 수 있도록 해야 함
- 반드시 모든 적합 아이템을 보여줄 필요는 없음
- 사용자가 충분히 만족할 수 있는 아이템을 발견하도록 하는 것이 중요

⇒ **“정답을 전부 보여주는 것”보다 “사용자가 만족할 만한 아이템을 빠르게 찾도록 하는 것”이 핵심**

### 추천 결과 정렬

적합 아이템 발견에서는 사용자의 기호에 잘 맞을 가능성이 높은 아이템부터 보여주는 것이 효과적

- 추천 가능성이 높은 아이템을 리스트 상단에 배치
- 사용자는 일반적으로 리스트를 위에서부터 확인함
- 적합도가 높은 아이템을 위쪽에 배치하면 사용자가 원하는 아이템을 빠르게 찾을 수 있음

⇒ 추천 결과의 **순서와 랭킹**도 UI/UX에서 중요함

### 리스트에 표시할 정보

리스트 형식에서는 한 화면에 여러 아이템을 보여주기 때문에 각 아이템에 표시할 수 있는 정보가 제한됨

따라서 사용자가 아이템을 선택하기 전에 판단에 필요한 핵심 정보를 적절하게 보여줘야 함

- 아이템 이름
- 대표 이미지
- 평점
- 가격
- 위치
- 주요 특징 등

정보가 너무 적으면 해당 아이템이 자신에게 맞는지 판단하기 어려움

정보가 너무 많으면 화면이 복잡해지고 중요한 정보를 찾기 어려움

⇒ **필요한 정보를 충분히 제공하되 지나치게 많은 정보를 보여주지 않는 균형이 중요**

### 사용 목적에 따라 보여줄 정보도 달라짐

같은 아이템이라도 사용자의 목적에 따라 필요한 정보가 달라질 수 있음

ex) 음식점 추천

- 사용자가 실제로 식당을 방문하려는 경우 → 위치, 가격, 평점, 영업시간 등 중요
- 사용자가 음식 사진을 보고 메뉴를 고르는 경우 → 음식 사진과 메뉴 정보가 더 중요

⇒ **아이템 자체가 아니라 사용자가 그 아이템을 어떤 목적으로 이용하는지를 고려해야 함**

### 여러 추천 리스트 제공

하나의 추천 알고리즘만 사용하여 하나의 리스트만 보여준다고 해서 항상 사용자의 취향에 맞는 아이템을 제공할 수 있는 것은 아님

따라서 여러 추천 알고리즘을 활용하여 서로 다른 성격의 추천 리스트를 제공할 수 있음

ex) 넷플릭스

- 인기 콘텐츠
- 사용자 취향 기반 추천
- 특정 장르 추천
- 새로 올라온 콘텐츠 등

### 여러 리스트를 사용하는 이유

- 하나의 알고리즘이 사용자의 모든 취향을 완벽하게 반영하기 어려움
- 서로 다른 기준의 추천을 제공하여 사용자가 선택할 수 있는 범위를 넓힐 수 있음
- 한 리스트에서 원하는 아이템을 발견하지 못하더라도 다른 리스트를 확인할 수 있음

⇒ **여러 추천 기준을 동시에 제공하여 적합한 아이템을 발견할 가능성을 높임**

### 여러 리스트의 UI

여러 리스트를 보여주는 대표적인 방법

- 탭을 이용하여 추천 리스트 전환
- 한 화면에 여러 추천 리스트를 동시에 표시
- 가로 스크롤을 이용하여 리스트별 아이템 탐색

ex) 넷플릭스 -지금 뜨는 콘텐츠, 내가 좋아할 만한 콘텐츠, 새로 올라온 콘텐츠 → 가로 스크롤

- 사용자는 화면을 크게 이동하지 않고 여러 추천 기준을 한 번에 확인할 수 있음
- 영상이나 음악 서비스처럼 하나의 화면에 많은 정보를 보여줘야 하는 서비스에서 특히 효과적

⇒ 추천 결과를 계산하는 것뿐 아니라 **여러 추천 결과를 어떻게 배치할지도 중요한 UI/UX 요소**

### 피드백을 이용한 추천 개선

매칭 애플리케이션처럼 아이템을 하나씩 보여주는 서비스에서는 사용자가 즉각적인 피드백을 남길 수 있음

ex) Tinder와 같은 서비스

- 오른쪽으로 넘김 → 관심 있음
- 왼쪽으로 넘김 → 관심 없음

### 피드백의 장점

- 사용자가 아이템을 평가하는 순간 바로 선호 데이터를 수집할 수 있음
- 사용자가 관심 없다고 표시한 아이템은 이후 추천에서 제외하거나 영향도를 낮출 수 있음
- 추천 시스템이 사용자의 취향을 빠르게 학습할 수 있음

### 주의할 점

- 사용자가 실수로 잘못된 피드백을 보낼 수 있음
- 한 번의 잘못된 선택으로 추천 결과가 지나치게 달라질 수 있음

따라서 이전에 입력한 피드백을 수정하거나 되돌릴 수 있는 기능을 제공하면 사용자 경험을 개선할 수 있음

## 2. 적합 아이템 나열

> 사용자가 자신의 목적을 달성하는 데 적합한 아이템을 가능한 한 모두 발견하도록 하는 것
> 

적합 아이템 발견과 비슷하지만 목표가 다름

- 적합 아이템 발견 → 사용자가 만족할 수 있는 아이템을 최소 하나 이상 찾으면 목적 달성
- 적합 아이템 나열 → 조건에 맞는 아이템을 가능한 한 빠짐없이 찾아야 함

ex) 이사할 집 찾기

- 사용자의 조건
    - 월세
    - 위치
    - 교통
    - 방 크기
    - 주변 환경 등
- 조건을 만족하는 집을 가능한 한 많이 비교하고 싶어함

ex) 특허 검색

- 이미 비슷한 특허가 존재하는지 확인해야 함
- 관련 특허를 하나만 찾는 것이 아니라 가능한 한 모두 확인해야 함

⇒ **적합 아이템 발견은 “좋은 것 하나 찾기”, 적합 아이템 나열은 “조건에 맞는 것을 최대한 빠짐없이 찾기”**

### 적합 아이템 나열에서 중요한 점

모든 결과를 사용자의 기호 순으로 정렬하는 것만이 항상 좋은 방법은 아님

- 아이템 수가 많으면 모든 결과를 하나씩 확인하기 어려움
- 사용자가 원하는 조건을 빠르게 좁힐 수 있도록 도와야 함

따라서 다음과 같은 기능이 중요

- 필터
- 검색 조건
- 정렬
- 조건 선택

ex) 지역, 가격, 면적, 등록일, 카테고리 등을 선택하여 후보를 좁힐 수 있도록 함

### 정렬 방식

사용자의 선호도만으로 정렬하는 것보다 서비스 목적에 따라 다양한 정렬 방식이 유용할 수 있음

- 최신순
- 등록일순
- 가격순
- 인기순
- 조건 일치도순

ex) 특허 검색

→ 예측 점수가 높은 특허부터 보여주는 것보다 최신 특허나 특정 조건에 맞는 순서로 보여주는 것이 사용자가 정보를 확인하기 더 편할 수 있음

⇒ **사용자가 많은 후보를 효율적으로 확인하도록 돕는 것이 핵심**

### 적합 아이템 수 표시

조건에 맞는 아이템이 몇 개 존재하는지 사용자에게 보여주는 것도 중요

ex) 조건에 맞는 결과 124개

- 결과가 너무 많으면 조건을 추가할 수 있음
- 결과가 너무 적으면 조건을 완화할 수 있음
- 사용자가 자신의 검색 조건이 적절한지 판단하기 쉬워짐

### 조건 저장 및 재사용

부동산이나 여행처럼 한 번의 방문만으로 결정을 내리지 않는 서비스에서는 이전 조건을 저장하는 기능이 유용함

- 사용자가 원하는 조건을 저장
- 다음에 서비스를 방문했을 때 같은 조건으로 다시 검색
- 새로운 아이템이 추가되면 다시 확인

⇒ 장기간에 걸쳐 아이템을 탐색하는 서비스에서는 **조건 저장과 재검색 기능**이 중요함

## 3. 아이템 계열 소비

> 열람하거나 소비하는 동안 추천된 아이템 계열 전체에서 가치를 느끼도록 하는 것
> 

대표적인 예

- 음악 스트리밍
- 동영상 스트리밍
- 뉴스 피드

사용자는 하나의 아이템만 소비하고 끝내는 것이 아니라 **여러 아이템을 연속적으로 소비**

ex) 음악 스트리밍 - 사용자가 기분이 좋아지는 음악을 듣기 시작했다고 가정

→ 첫 곡 하나만 좋아도 되는 것이 아니라 이후에 재생되는 곡들도 비슷한 분위기와 만족감을 유지해야 함

### 아이템 계열 소비에서 중요한 점

각 아이템 하나하나의 추천 정확도뿐만 아니라 **추천되는 아이템의 전체 흐름**이 중요함

- 연속해서 비슷한 분위기를 유지
- 사용자의 현재 목적과 기분을 지속적으로 반영
- 자연스럽게 다음 아이템으로 이어지도록 구성

### 사용자의 상황 변화 반영

사용자의 상황이나 목적은 시간에 따라 변할 수 있음

ex) 우울한 음악을 듣기 시작한 사용자

- 계속 우울한 음악만 추천하면 오히려 만족도가 낮아질 수 있음
- 사용자의 반응을 파악하여 분위기를 자연스럽게 전환할 필요가 있음

ex) 크리스마스 음악

- 크리스마스 기간에는 만족도가 높을 수 있음
- 기간이 지나도 계속 크리스마스 음악을 추천하면 만족도가 낮아질 수 있음

⇒ **사용자의 현재 상황과 시점을 함께 고려해야 함**

### 다양성의 중요성

아이템 계열 소비에서는 사용자가 좋아하는 것만 반복적으로 추천한다고 항상 좋은 것은 아님

ex) 음악 서비스 - 사용자가 좋아하는 음악과 비슷한 곡만 계속 추천

→ 처음에는 만족할 수 있음

→ 반복되면 새로움이 없어지고 지루함 발생

따라서 사용자가 좋아하는 아이템, 사용자가 좋아할 가능성이 있는 새로운 아이템을 적절히 섞어주는 것이 중요함

⇒ **정확도뿐만 아니라 다양성과 새로움도 고려해야 함**

## 중요하게 본 내용

- 가장 기억에 남는 내용: 사용자가 좋아하는것도 추천해줘야되고 또 너무 좋아하는것만 계속 추천해도 사용자가 질릴 수 있음
- 중요하다고 생각한 이유: 추천시스템 너무 고려해야 할게 많다.
- 다른 주제와 연결되는 부분: 없음

## 질문 및 토론거리

- 이해가 어려웠던 부분:
- 팀원들과 함께 이야기할 질문:
▶ 같은 분위기의 음악에서 자연스럽게 다른 분위기의 음악으로 넘어가는 기준점 설정? → 해당 음악이 나오는 스테이션에서는 비슷한 분위기를 유지하되 홈화면의 추천탭에서는 밝은 분위기의 음악도 추천해서 사용자가 클릭하도록 유도한다.
