### 내용 1: 추천 시스템 개발에는 세 가지 역량이 함께 필요하다

- 추천 시스템을 개발하려면 해결할 문제를 정하는 능력, 데이터를 분석하고 추천 방법을 만드는 능력, 이를 실제 서비스에서 운영하는 능력이 필요하다.
1. **비즈니스 문제 해결 능력**
    - 추천으로 해결할 문제와 목표 설정
    - 클릭·구매·시청 시간 등 개선할 사용자 행동 결정
    - 목표 달성 여부를 확인할 KPI 설정 필요함
    - KPI: 핵심 성과 지표
2. **데이터 사이언스 능력**
    - 데이터 분석 및 추천 알고리즘 구현
    - 데이터 특성과 알고리즘의 장단점 파악
    - 간단한 추천 방법부터 적용한 뒤 결과에 따라 개선
3. **데이터 엔지니어링 능력**
    - 데이터 가공·추천 계산·결과 저장 과정 구축
    - 계산 시간과 서비스 운영 조건 고려
    - 추천 시스템의 안정적인 실행과 관리 담당
- **목표와 지표 설정의 중요성**
    - 무엇을 좋은 추천으로 볼 것인지 먼저 정해야 함
    - 책의 유튜브 사례: 시청 동영상 수 → 실제 시청 시간 중심으로 지표 변경
    - 평가 지표에 따라 추천 방향과 필요한 데이터도 달라짐
    - 목표 측정에 필요한 데이터가 없다면 로그 추가 수집 필요함
- **팀 단위 협업**
    - 세 가지 역량을 한 사람이 모두 갖추기는 어려움
    - 역할별 담당자 간 목표·데이터·운영 제약 공유 필요함

### 내용 2: 프로젝트는 목표와 문제를 구체화하는 것부터 시작한다

- **추천 시스템 프로젝트의 전체 절차**
과제 정의
가설 수립
데이터 설계·수집·가공
알고리즘 선정
학습·파라미터 튜닝
시스템 구현
평가 및 개선
- **과제 정의**
    - 추상적인 목표를 구체적인 지표로 세분화
    - 예: 매출 증가 → 사용자 수 증가 또는 사용자 1인당 매출 증가
    - 현재 상태와 목표 사이의 차이 확인
    - 사용자가 어려움을 겪는 지점 파악
- **문제 파악 방법**
    - 행동 로그: 검색·클릭·이탈 등 실제 행동 확인
    - 사용자 인터뷰: 행동의 이유와 불편 사항 파악
    - 두 방법을 함께 활용하면 문제를 더 정확히 이해할 수 있음
- **가설 수립과 우선순위 결정**
    - 해결 방법별 효과·비용·중요도 비교
    - 검색 정렬이나 상품 정보 표시 개선만으로 해결 가능한지 검토
    - 추천 시스템 도입 여부도 비용 대비 효과를 기준으로 판단해야 함
- **추천에 활용하는 데이터**
    - 사용자·아이템의 콘텐츠 정보
        - 사용자 프로필과 선호
        - 아이템 설명·태그·카테고리
    - 사용자와 아이템의 상호작용 정보
        - 열람·북마크·구매·시청·평가 기록
- **데이터 준비 시 확인 사항**
    - 누락되거나 잘못 입력된 정보 정리
    - 봇 등으로 발생한 부적절한 로그 제거
    - 서비스 초기에는 상호작용 기록이 부족할 수 있음
    - 확보된 아이템 정보로 가능한 추천부터 검토
    - 데이터 양과 함께 활용 가능한 품질인지 확인 필요함

### 내용 3: 알고리즘은 정확도·비용·운영 조건을 함께 고려해 선택한다

- **알고리즘 선정 기준**
    - 추천 정확도
    - 계산 시간
    - 필요한 데이터
    - 개발 및 운영 비용
    - 비즈니스 목표와의 적합성
- **초기 개발 방향**
    - 간단한 알고리즘부터 구현
    - 결과 확인 후 단계적으로 개선
    - 작은 정확도 향상에도 큰 비용이 들 수 있음
- **학습 및 검증**
    - 학습과 파라미터 조정 수행
    - 과거 데이터로 추천 결과 검증
    - 정밀도·재현율 등 지표 확인
    - 실제 추천 아이템이 적절한지도 함께 확인
    - 구체적인 추천 사례로 담당자 간 결과 비교·논의 가능함
- **데이터 편향 주의**
    - 평가 편향
        - 상품에 호감이 있는 사용자가 주로 평가를 남길 수 있음
        - 높은 별점이 실제 전체 사용자 의견을 대표하지 않을 수 있음
    - 노출 위치에 따른 편향
        - 검색 결과 상단 아이템은 눈에 잘 띄어 클릭될 가능성이 높음
        - 클릭이 많다는 이유만으로 선호도가 높다고 단정하기 어려움
    - 편향을 고려하지 않으면 기존 노출 방식이 추천 결과에도 반복될 수 있음
- **시스템 구현 시 고려 사항**
    - 학습 및 추천 결과 갱신 주기
    - 신규 사용자·신규 아이템에 대한 추천 방법
    - 데이터 파이프라인 구성
    - 파이프라인: 데이터 가공 → 추천 계산 → 결과 저장의 처리 흐름

## 중요하게 본 내용

- **가장 기억에 남는 내용:**
추천 시스템을 개발하기 전에 목표와 KPI를 정하고, 현재 문제에 추천이 적절한 해결 방법인지 검토해야 한다는 점이다.
- **중요하다고 생각한 이유:**
추천 정확도가 높아도 사용자가 겪는 문제나 서비스의 목표를 해결하지 못하면 개발 효과가 작을 수 있기 때문이다.
- **다른 주제와 연결되는 부분:**
소프트웨어 개발의 요구사항 분석과 연결된다. 다음 주차의 UI/UX 설계에서도 구매, 재방문, 신뢰 형성 등 어떤 행동을 돕고 싶은지 먼저 정해야 한다.

## 질문 및 토론거리

- **이해가 어려웠던 부분**
    - 클릭 기록에 사용자의 선호와 화면상의 노출 위치가 함께 영향을 준다면, 실제 선호를 어떻게 구분하고 평가에 반영할 수 있을까?
- **팀원들과 함께 이야기할 질문**
    - 1. 동영상 서비스의 추천을 평가한다면 **클릭 수, 시청 시간, 재방문** 중 무엇을 핵심 지표로 삼는 것이 적절할까?
    ▶ 시청 시간 > 클릭 수 > 재방문(카테고리에 따라 상이함)
    - 2. **사용자 기록이 거의 없는** 서비스에서는 어떤 **정보**와 **간단한 추천 방식**부터 활용할 수 있을까?
    ▶ 인기도, 회원 가입 시 데이터(나이, 성별 등), 가입 경로, 설문 조사 방식
    ▶ 서비스 형식에 맞는 더미 데이터 생성.
        
        ▶ 무심코 사용자 기록이 풍부한 기준으로 서비스를 설계하는 것을 주의해야한다.
        
        ▶ 서비스하는 목적이나 용도에 따라 초기 데이터 자체에 대한 설계하는 방식 또한 크게 달라지기 때문에 프로젝트 시작 단계부터 꼼꼼하게 구상하는 것이 중요하다.
