# 검색 시스템과 추천 시스템

정보를 찾는 방식과 개인화된 제안의 차이, 그리고 두 시스템이 함께 작동하는 구조

**핵심 한눈에 보기**

검색은 사용자가 표현한 필요를 찾아주고, 추천은 사용자의 맥락과 행동을 바탕으로 아직 찾지 않은 후보를 제안한다.

## 검색 시스템: 명시적인 질문에 답하기

검색 시스템은 사용자가 입력한 키워드나 질문을 바탕으로 관련 문서, 상품, 게시물 등을 찾아 순위를 매겨 보여준다. 초기에는 검색어와 정확히 일치하는 문서를 찾았고, 이후에는 유사어와 문맥을 고려해 검색 범위를 넓혔다. 웹 검색에서는 페이지 내용뿐 아니라 페이지 사이의 링크 관계도 활용할 수 있다. 본문은 PageRank를 링크 정보를 이용해 중요 페이지를 판단하는 대표 사례로 소개한다.

## 검색과 추천의 차이

| 비교 기준 | 검색 시스템 | 추천 시스템 |
| --- | --- | --- |
| 사용자 의도 | 찾고 싶은 대상이나 주제를 대체로 알고 있음 | 무엇을 원할지 명확히 말하지 않아도 됨 |
| 입력 | 검색어, 필터 등 명시적 요청 | 열람·구매·평가 등 과거 행동과 현재 맥락 |
| 시스템 동작 | 질의와 관련성이 높은 후보를 찾아 순위화 | 관심 가능성이 높은 후보를 추정해 먼저 제시 |
| 상호작용 유형 | Pull 방식: 사용자가 정보를 요청 | Push 방식: 시스템이 제안을 전달 |

## 두 시스템은 서로 보완한다

검색은 사용자가 알고 있는 필요를 빠르게 충족시키고, 추천은 탐색의 폭을 넓혀 사용자가 미처 생각하지 못한 선택지를 발견하게 한다. 예를 들어 영상 서비스에서 제목을 검색해 작품을 본 뒤, 시청 이력이 쌓이면 비슷한 취향의 콘텐츠가 추천된다. 쇼핑 서비스에서도 검색 결과와 상품 상세 페이지를 이용하는 동안 추천이 함께 나타난다. 따라서 실제 서비스는 검색과 추천을 함께 제공하는 경우가 많다.

# 추천 시스템의 활용과 설계

행동 데이터로 관심을 추정하고, 사용자와 서비스의 목표에 맞는 순서로 제안한다

## 4. 추천 시스템은 어떻게 후보를 고르는가

추천은 사용자의 선호를 직접 묻지 않아도 과거 행동에서 관심의 단서를 찾는다. 조회·구매·평가 이력이나 비슷한 사용자의 선택을 활용해 다음에 좋아할 만한 항목을 추정한다. 텍스트로 분위기를 표현하기 어려운 음악·패션처럼 검색어만으로 원하는 대상을 설명하기 힘든 영역에서도 유용하다. 과거에 본 상품과 비슷한 상품을 제안하면 사용자가 새로운 후보를 더 쉽게 발견할 수 있다.

**행동·맥락 데이터 → 관심 신호 추정 → 후보 순위화 → 개인화된 제안**

## 5. 활용 가치와 평가 관점

추천은 정보가 많은 환경에서 선택을 돕고, 사용자가 서비스 안에서 관심 있는 항목을 더 빨리 찾도록 한다. 본문은 넷플릭스 시청의 약 80%, 아마존 매출의 약 35%가 추천 시스템과 관련된다는 수치를 사례로 인용한다. 이는 책에 실린 설명용 수치이며, 서비스의 시기와 산정 방식에 따라 달라질 수 있다. 추천을 설계할 때는 클릭 수만 보지 말고 사용자 경험과 서비스의 사업 목표를 함께 정해야 한다.

## 6. 설계할 때 기억할 점

- **목표를 먼저 정하기** 사용자에게 어떤 도움을 줄지, 서비스가 어떤 가치를 얻을지 구체화한다.
- **순위화 방법을 선택하기** 인기도 기반 랭킹은 많은 사람이 선택한 항목을, 협업 필터링은 비슷한 취향을 보인 사용자들의 행동을 활용한다.
- **맥락과 개인화를 고려하기** 같은 검색어라도 사용자와 과거 행동에 따라 적절한 결과가 달라질 수 있다.
- **검색과 추천을 연결하기** 검색은 명시적인 요구를 해결하고, 추천은 탐색을 이어 주므로 함께 설계하면 발견 경험을 넓힐 수 있다.

## 정리

검색은 사용자가 표현한 필요를 중심으로 결과를 찾고, 추천은 행동과 맥락에서 선호를 추정해 후보를 제시한다. 좋은 서비스는 두 기능을 적절히 결합해 정보 탐색과 선택을 지원한다.

## 중요하게 본 내용

- **가장 기억에 남는 내용:**
    
    검색은 사용자가 직접 표현한 필요를 해결하고, 추천은 사용자의 행동과 맥락을 바탕으로 아직 찾지 않은 후보를 제안한다는 점이 기억에 남았다. 실제 서비스에서는 두 기능이 따로 작동하기보다 함께 제공된다.
    
- **중요하다고 생각한 이유:**
    
    검색만으로는 사용자가 이미 알고 있는 대상만 찾기 쉽고, 추천만으로는 사용자가 원하는 것을 정확히 찾기 어려울 수 있다. 두 기능을 함께 사용하면 필요한 정보를 찾는 동시에 새로운 선택지도 발견할 수 있기 때문이다.
    
- **다른 주제와 연결되는 부분:**
    
    추천 시스템은 사용자의 열람·구매·평가 기록을 분석한다는 점에서 데이터 분석과 개인화 기술에 연결된다. 또한 어떤 결과를 먼저 보여줄지 정한다는 점에서 검색 결과의 순위화와도 관련이 있다.
    

## 질문 및 토론거리

- **이해가 어려웠던 부분:**
    
    사용자의 과거 행동 데이터가 구체적으로 어떤 과정을 거쳐 관심 있는 항목을 추정하고, 추천 순위로 이어지는지 궁금했다.
    
- **팀원들과 함께 이야기할 질문:**
    
    ### 검색과 추천을 함께 사용하는 구체적인 사례
    
    영상 서비스에서 사용자가 검색창에 영화 제목을 입력하면, 검색 시스템은 제목과 관련된 작품을 찾아 보여준다. 사용자가 그중 한 작품을 시청하면, 서비스는 시청 기록을 바탕으로 비슷한 장르나 주제의 영상을 추천할 수 있다. 이처럼 검색은 사용자가 찾고 있는 작품을 보여주고, 추천은 시청 이후 관심을 가질 만한 다른 작품을 제안한다.
    
    ### 사용자의 과거 데이터는 어떤 방식으로 활용되는가?
    
    서비스는 사용자의 계정에 검색 기록, 시청한 영상, 시청 시간, 좋아요나 평가 같은 행동 기록을 연결해 저장한다. 추천할 때는 이 기록을 불러와 사용자가 어떤 장르나 주제에 관심을 보였는지 추정한다. 예를 들어 특정 장르의 영상을 끝까지 시청했다면 해당 장르에 관심이 있다는 신호로 참고할 수 있다. 비슷한 영상을 본 다른 사용자들의 선택도 함께 살펴 추천 후보와 순서를 정할 수 있다.
    
    또한 최근 검색이나 현재 시청 중인 영상처럼 현재 맥락을 반영하면, 같은 사용자라도 상황에 따라 다른 추천을 받을 수 있다. 자세한 방식은 서비스마다 다르지만, 과거 행동과 현재 맥락을 바탕으로 관심 가능성이 높은 항목을 골라 보여주는 것이 개인화 추천의 기본적인 원리다.
    

## 스터디 후 보완

- **새롭게 이해한 내용:**
    
    사용자의 과거 데이터는 열람·구매·평가 기록처럼 관심을 나타내는 신호로 활용될 수 있다. 시스템은 이런 기록과 비슷한 사용자의 선택을 바탕으로 관심 가능성이 높은 후보를 추정하고 순위를 정한다. 같은 검색어를 입력하더라도 사용자와 과거 행동에 따라 결과나 추천이 달라질 수 있다.
    
- **수정하거나 추가할 내용:**
    
    추천 시스템의 효과를 평가할 때 클릭 수만 살피는 것이 아니라, 사용자 경험과 서비스의 목표도 함께 고려해야 한다는 내용을 추가하고 싶다. 또한 추천에 활용되는 행동 데이터와 현재 맥락의 예시를 더 찾아 정리하면 추천 과정이 더 구체적으로 이해될 것 같다.
