## 추천 시스템

> 사용자가 여러 선택지 중에서 자신에게 가치 있는 아이템을 선택할 수 있도록 의사결정을 지원하는 시스템
> 
- 사용자가 직접 키워드를 입력해 검색하지 않아도 사용자의 정보나 행동 데이터를 활용하여 사용자가 관심을 가질 가능성이 높은 아이템을 대신 찾아 제시함
- 대표적인 예시 → 아마존(Customers who vied this item also viewd). 유튜브, 넷플, 트위터, 스포티파이

### 추천 시스템을 사용하는 이유

- 사용자 관점 : 정보 탐색 비용 감소 → 새로운 아이템 발견 → 사용자 경험 향상
- 기업 관점 : 상품 구매 유도 → 콘텐츠 소비 증가 → **서비스 제휴시간 증가** → 사용자 만족도 향상

### 의사 결정 지원

- 추천 시스템은 실제로 사용자가 추천한 아이템을 보고 클릭하고 구매하도록 만드는 것까지 고려해야 함
- 어떤 아이템을 추천할 것인가?
- 어디에 추천 아이템을 표시할 것인가?
- 언제 추천할 것인가?
- 어떤 방식으로 사용자에게 전달할 것인가?
- ex) 상품 구매 시점에 관련 상품 추천, 사용자가 상품을 둘러보는 동안 관련 상품 보여줌

⇒ 추천시스템은 **데이터 + 알고리즘 + 사용자에게 보여주는 방법**을 함께 고려해야 하는 시스템‼️

## 추천 시스템의 역사

인터넷의 발전 → 대량의 정보 생성 → 사용자가 원하는 정보를 직접 찾기가 어려움 → 수많은 후보에서 적절한 정보를 선택할 수 있도록 돕는 기술 필요 → 추천 시스템 등장

### Tapestry

- 추천 시스템의 초기 사례
- 1990년대 Xerox PARC의 연구자 David Goldberg 등이 제안
- 늘어나는 이메일 가운데 사용자가 관심을 가질 만한 이메일을 찾기 위해 개발
- 단순한 필터링 X → 협업 필터링 (Collaborative Filtering) & 사용자가 이메일을 평가하는 방식 이용
- 이후 추천 시스템 연구의 기반이 됨

### 전자상거래의 발전

- 상품 종류 많아짐 → 사용자가 원하는 상품을 직접 찾기 어려워짐
- 사용자의 구매 및 탐색 데이터를 활용하여 상품 추천 시작
- ex) 아마존의 이 상품을 본 사람들이 함께 본 상품

### Netflix Prize

- 2006년 넷플릭스가 추천 알고리즘의 성능을 개선하기 위해 개최
- 약 10억 건의 영화 평가 데이터를 공개
- 기존 추천 알고리즘보다 더 높은 성능을 가진 알고리즘을 개발하는 경쟁을 진행
- 이를 계기로 대규모 데이터를 활용한 추천 알고리즘 연구가 활발해짐

### ACM ResSys

- 추천 시스템 분야의 대표적인 국제 학회
- 2007년부터 개최되기 시작
- 추천 시스템이 학계뿐만 아니라 산업에서도 중요해지면서 관련 연구와 개발이 지속적으로 증가 → 단순한 부가 기능이 아니라 유튜브 넷플 등 서비스에서 핵심 기능으로 사용

## 추천 시스템의 종류

### 입력

추천 시스템에서 사용하는 데이터는 크게 콘텐츠 정보와 인터렉션 정보로 나눌 수 있음

#### 콘텐츠 정보

사용자 또는 아이템 자체가 가지고 있는 정보

- 사용자 정보
    - 나이, 성별, 주소, 관심 카테고리, 선호 가격대 등…
    - 회원가입이나 설문을 통해 사용자 정보를 얻을 수 있음
- 아이템 정보
    - 상품이나 콘텐츠가 가지고 있는 특징
    - 상품 설명, 카테고리, 가격, 제작자/브랜드

⇒ **내용 기반 필터링 (Content-based Filtering)** : 콘텐츠 정보를 이용하여 추천하는 방식

#### 인터렉션 정보

사용자가 서비스 안에서 어떤 행동을 했는지에 대한 데이터

- ex) 조회, 클릭, 구매, 평점, 북마크, 좋아요 → 사용자가 서비스를 이용할 수록 계속 쌓이는 데이터
- 실시간으로 계속 업데이트 → 사용자의 최근 관심사를 반영하기 좋음
- 콜드 스타트 문제 : 새로운 사용자나 새로운 아이템은 아직 행동 데이터가 거의 없기 때문에 추천하기 어려움

⇒ **협업 필터링 (Collaborative Filtering)** : 인터렉션 정보를 이용하는 대표적인 추천 방법

### 프로세스 (추천 설계)

입력된 데이터를 이용하여 추천 아이템을 결정 하는 방식은 다음 세 가지로 구분할 수 있음

#### 개요 추천

> 개인화를 적용하지 않고 모든 사용자에게 동일한 기준으로 아이템을 추천하는 방법
> 
- 인기순, 신규순, 가격순 등
- ex) 아마존의 베스트셀러 상품, 쇼핑몰의 인기 상품 목록
- 구현이 단순, 개인 사용자 데이터가 없어도 사용 가능
- 트렌드가 중요한 상품, 뉴스, 신상품, 유행에 민감한 콘텐츠 등에서 효과적
- 사용자 개인의 취향을 고려하지 못함
- 상품 변화가 많지 않은 서비스에서는 항상 비슷한 상품만 추천

#### 연관 아이템 추천

> 현재 보고 있는 아이템과 관련성이 높은 다른 아이템을 추천하는 방식
> 
- ex) 이 아이템을 확인한 사람은 이런 아이템도 확인했습니다
- 사용자가 특정 상품을 보고 있을 때 비슷하거나 함께 관심을 가질 만한 상품을 보여줌
- 연관 아이템을 찾는 방법

#### 연관 아이템을 찾는 방법

#### 콘텐츠 기반

아이템이 가지고 있는 특징을 비교하여 비슷한 아이템을 찾는 방법

- 같은 카테고리
- 비슷한 상품 설명
- 비슷한 키워드
- 비슷한 속성
- ex) 사용자가 운동화를 보고 있다면 같은 카테고리나 비슷한 특징의 운동화를 추천

⇒ **내용 기반 필터링(Content-based Filtering)**을 활용하여 아이템 간 유사도를 계산

#### 협업 필터링 기반

사용자들의 행동 데이터를 이용하여 아이템 사이의 관계를 찾는 방법

- 특정 아이템을 본 사람들이 어떤 다른 아이템을 함께 봤는지 확인
- ex) A 상품을 본 사용자들이 B 상품도 자주 봄 → A와 B를 연관 아이템으로 판단
- 아이템의 카테고리나 키워드만으로 표현하기 어려운 관계도 사용자 행동을 통해 파악할 수 있음

⇒ **협업 필터링(Collaborative Filtering)** 을 활용하여 함께 조회되거나 구매되는 아이템을 추천

#### 아이템 유사도 설계 시 고려할 점

- 단순히 비슷한 아이템만 추천하는 것이 항상 좋은 것은 아님
- 사용자의 현재 상황이나 추천 목적에 따라 어떤 아이템을 연관 아이템으로 볼 것인지 달라질 수 있음

ex) 사용자가 프린터를 구매하기 전

→ 성능이나 가격이 비슷한 다른 프린터 추천

ex) 사용자가 프린터를 구매한 이후

→ 잉크, 토너, 용지 등 함께 사용할 수 있는 상품 추천

⇒ 추천 목적에 따라 **어떤 관계를 유사하다고 정의할 것인지**가 중요함

#### 롱테일 문제

> 일부 인기 아이템에 사용자 행동과 추천이 계속 집중되는 현상
> 
- 인기 상품 → 조회·구매 데이터가 많이 쌓임
- 데이터가 많기 때문에 추천에 더 자주 등장
- 추천에 많이 등장하므로 다시 클릭과 구매가 증가
- 결과적으로 인기 아이템에 데이터와 추천이 계속 집중될 수 있음

⇒ 인기 아이템만 반복적으로 추천되면 사용자가 다양한 아이템을 발견하기 어려워질 수 있으므로, 상황에 따라 인기 아이템의 영향을 조절할 필요가 있음

#### 개인화 추천

> 사용자의 프로필이나 과거 행동 이력을 기반으로 사용자마다 서로 다른 아이템을 추천하는 방법
> 
- 사용자 개인의 취향이나 관심사를 반영
- 사용자마다 추천 결과가 달라짐
- 사용자 프로필이나 인터렉션 데이터를 활용할 수 있음
- ex) 과거 조회 기록, 클릭 기록, 구매 기록, 평점, 관심 카테고리 등

⇒ 콘텐츠 정보와 인터렉션 정보를 각각 활용하거나 두 가지를 함께 활용할 수 있음

#### 콘텐츠 기반 개인화

사용자의 프로필 정보와 아이템 정보를 비교하여 사용자에게 맞는 아이템을 추천

- 사용자의 나이, 성별, 거주지, 관심 카테고리 등의 정보 활용
- ex) 사용자의 거주지를 기준으로 가까운 장소나 매장 추천
- 사용자가 선호하는 카테고리와 비슷한 특징을 가진 아이템 추천

#### 인터렉션 기반 개인화

사용자의 과거 행동 데이터를 바탕으로 사용자의 취향을 파악하여 추천

- 과거 조회 기록
- 클릭 기록
- 구매 기록
- 평점
- 북마크 등

ex) 사용자가 특정 장르의 영화를 자주 시청함

→ 비슷한 영화를 좋아하는 사용자들의 데이터를 참고

→ 해당 사용자가 아직 보지 않은 영화를 추천

⇒ 협업 필터링 등을 이용하여 사용자의 과거 행동으로부터 선호도를 추정할 수 있음

#### 열람 이력을 이용한 추천

사용자가 과거에 열람했던 아이템을 다시 보여주는 가장 간단한 개인화 추천 방식

- ex) 아마존의 Your Browsing History
- 과거에 본 상품을 다시 표시
- 구현 비용이 비교적 적음
- 사용자가 한번 확인했던 상품을 다시 찾는 경우가 많은 서비스에서 효과적

특히 다음과 같은 서비스에서 활용 가능

- 쇼핑몰
- 동영상 서비스
- 음악 서비스

#### 열람 이력 + 연관 아이템 추천

사용자가 과거에 본 아이템을 그대로 보여주는 것에서 더 나아가 해당 아이템과 관련된 다른 아이템을 추천하는 방식

사용자가 최근 본 아이템

→ 해당 아이템의 연관 아이템 탐색

→ 사용자에게 추천

- 기존 연관 아이템 추천 구조를 이용할 수 있음
- 비교적 간단하게 개인화 추천을 구현할 수 있음

#### 개인화 추천에서 인터렉션 데이터가 중요한 이유

- 조회나 클릭 등의 사용자 행동은 사용자의 현재 관심사를 빠르게 반영할 수 있음
- 프로필 정보보다 실시간으로 변화하는 사용자의 관심을 파악하기에 적합함
- 사용자 행동이 누적될수록 더욱 세밀한 개인화가 가능함

⇒ 일반적으로 사용자와 아이템의 인터렉션을 활용한 개인화 추천은 사용자의 흥미나 기호를 실시간으로 반영할 수 있기 때문에 클릭이나 구매 예측 성능을 높이는 데 효과적임

### 출력 (추천 결과 제시)

> 추천 시스템이 계산한 추천 아이템을 실제 사용자에게 보여주는 단계
> 
- 좋은 추천 아이템을 계산하는 것만으로는 충분하지 않음
- 아무리 좋은 추천 결과라도 사용자에게 적절하게 노출되지 않으면 사용자의 행동으로 이어지기 어려움
- 따라서 **어디에서, 언제, 어떤 방식으로 추천할 것인지**도 중요함

### 추천 결과를 제시하는 방법

- 웹 페이지에 표시
- 앱 화면에 표시
- 이메일 전송
- 푸시 알림
- 쿠폰 발송 등

### 추천 위치와 시점

사용자가 서비스를 이용하는 상황에 따라 적절한 추천을 제공해야 함

ex) 상품 상세 페이지 → 현재 보고 있는 상품과 비슷한 상품 추천

ex) 장바구니 → 함께 구매하면 좋은 상품 추천

ex) 상품 구매 완료 이후 → 관련 소모품이나 액세서리 추천

⇒ 같은 추천 알고리즘을 사용하더라도 **추천을 보여주는 위치와 시점에 따라 사용자의 반응이 달라질 수 있음**

### 추천 시스템에서 출력이 중요한 이유

- 추천된 아이템을 사용자가 실제로 열람하거나 구매하도록 만드는 것이 중요함
- 추천 결과의 노출 방식이 좋지 않으면 좋은 알고리즘을 사용하더라도 효과가 떨어질 수 있음
- 따라서 추천 알고리즘뿐만 아니라 사용자 경험과 추천 결과 제시 방식까지 함께 고려해야 함

- 가장 기억에 남는 내용: 추천시스템은 알고리즘만 중요한게 아니라 구매자가 실제로 추천 아이템을 유지하게 연결되게 하는것이 중요하다
- 중요하다고 생각한 이유: 개발 외적으로도 사용자에게 어떻게 하면 추천시스템의 만족도를 높일 수 있는지 고려해야겠다고 생각했다.
- 다른 주제와 연결되는 부분: 출력 파트가 2주차 사용자 목적에 적합한 UI UX 사례로 연결된다.
